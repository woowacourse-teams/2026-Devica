# 개선 PR

Recommendation Improver 가 올리고, 팀원이 검토한다. 머지되지 않으면 Feedback Analyzer 가 반려 사유(팀원 리뷰·댓글)를 읽는다. 어디에 놓이는지는 [binding.md](../binding.md)에 있다.

| 항목 | 내용 |
|---|---|
| 근거 피드백 | 근거 피드백마다 머지되면 닫히게 `Closes #` 로 연결 |
| 변경 | 정의서 경로, 바꾼 규칙(`criterion`, `when`)과 전후 값 또는 문장 |
| 이유 | 개선 지시 링크와 그 이유 |
| 결과 변화 | 재현 사례의 결과 전→후. 앞서 더한 다른 `피드백 #` 사례 중 결과가 바뀐 것도 적는다 |
| 배포되지 않은 변경 | 바꾸는 규칙의 `criterion` 에 `develop` 과 `main` 이 다른 규칙이 있으면 그 목록. 운영 사용자가 겪을 변화가 결과 변화와 다를 수 있음을 밝힌다 |
| 같은 규칙의 최근 변경 | 바꾸는 규칙의 `develop` 변경 이력. 고쳤다 되돌리는 변경인지 검토하는 데 쓴다 |
| 영향 범위 | 스냅숏 전체 사례 수, 결과 값이 바뀐 사례 수(고친 규칙의 조건에 해당하는 답별로 나눔), 근거 문장만 바뀐 사례 수, 대표 사용자(테스트 코드의 `PERSONAS`) 중 바뀐 것 |
| 지표 추정 표시 | 지시의 `basis` 가 `METRIC_ESTIMATE` 일 때만. 추정한 항목·방향이 그럴듯한지 확인하라는 안내 |

커밋과 PR 은 [팀 컨벤션](../../../docs/팀_컨벤션.md)을 따른다.
