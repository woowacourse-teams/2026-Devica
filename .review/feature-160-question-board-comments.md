## 게시판 사이드 탭 검증

- 제품·사용 목적이 없는 `/board`에서 첫 사용 가능한 제품·사용 목적을 자동 선택해 질문 목록을 바로 표시함.
- 데스크톱은 제품 사이드 탭, 모바일은 가로 제품 탭과 사용 목적 탭으로 표시하며 페이지 전체에 가로 넘침이 없음.
- 지원하지 않는 제품·사용 목적은 준비 중으로 표시하고 선택을 막음.
- 선택한 제품·목적·페이지를 URL로 유지하고, 직접 진입·새로고침·뒤로 가기에서도 복원함.
- 다른 제품을 고르면 해당 제품의 첫 사용 가능한 목적을 자동 선택하고 첫 페이지로 이동하며, 다른 목적을 고르면 첫 페이지로 이동함.
- 테스트 API에서 여러 제품·목적을 제공하고 응답을 지연해 빠르게 전환했을 때, 이전 목적·게시글 응답이 새 선택을 덮어쓰지 않음을 확인함.
- 제품·사용 목적·게시글 조회 실패와 재시도, 각 빈 결과를 구분함. 목적·게시글 조회 실패 중에도 제품 탐색을 유지함.
- 잘못된 제품·목적 코드로 직접 들어오면 안내와 탭을 통해 복구할 수 있음.
- 글쓰기, 댓글이 있는 상세 화면, 목록 복귀와 페이지 이동 확인.
- 추천 흐름의 제품·사용 목적 카드와 다음 버튼을 브라우저에서 확인했다. 최초 사이드 탭 구현은 공용 `SelectionView`, 추천 화면, 공통 헤더·스타일을 수정하지 않았고, 후속 정리에서는 `SelectionView`의 호출되지 않는 게시판 전용 분기만 제거했다.
- 위 검증은 로컬 테스트 API로 수행했다.

## 게시판 기본 선택 검증

- `/board` 직접 진입 시 노트북·백엔드 개발이 선택되고, 선택 안내 없이 목록이 표시됨을 확인함.
- 여러 제품·목적의 API 응답 순서를 뒤집어도 화면에 표시한 탭 순서의 첫 사용 가능한 항목을 선택함.
- 제품만 선택된 주소에서는 목적을 자동 선택하며, 준비 중인 목적은 건너뜀.
- 직접 선택한 모니터·디자인·2페이지를 새로고침해도 유지함.
- 홈에서 게시판에 진입한 뒤 뒤로 가기를 한 번 누르면 홈으로 돌아옴. 자동 선택은 방문 기록을 추가하지 않음.
- 지원하는 목적이 없는 경우 기존 빈 상태를 표시하며 잘못된 기본값으로 이동하지 않음.
- 홈의 제품 카드와 다음 버튼을 확인함. 기본 선택 수정은 `BoardBrowseView.tsx`에 한정함.
