- 로컬 테스트 API와 브라우저로 공유 링크 직접 진입, 작성 순 댓글·익명·시각 표시, HTML의 일반 텍스트 렌더링 확인.

- 공백만 입력했을 때 등록 차단, 1,000자 등록 성공, 1,001자 등록 차단 확인.

- 빈 201 응답과 JSON 본문이 있는 201 응답 모두 입력 초기화·댓글 재조회 확인.
- 등록 성공 후 재조회만 실패했을 때 성공 안내와 조회 오류를 구분하며, 재시도로 새 댓글을 확인할 수 있음.
- 등록 후 게시글 목록으로 돌아오면 갱신된 댓글 수를 조회하며, 댓글 없는 글의 0도 표시함.
- 등록 중 다른 게시글로 이동했을 때 이전 응답이 화면·입력값을 덮어쓰지 않음.
- 모바일·데스크톱 배치와 긴 댓글의 가로 넘침 없음 확인.

## 게시판 사이드 탭 검증

- 제품·사용 목적이 없는 `/board`에서 제품 탭 → 사용 목적 탭 → 질문 목록으로 같은 화면 안에서 전환함.
- 데스크톱은 제품 사이드 탭, 모바일은 가로 제품 탭과 사용 목적 탭으로 표시하며 페이지 전체에 가로 넘침이 없음.
- 지원하지 않는 제품·사용 목적은 준비 중으로 표시하고 선택을 막음.
- 선택한 제품·목적·페이지를 URL로 유지하고, 직접 진입·새로고침·뒤로 가기에서도 복원함.
- 다른 제품을 고르면 이전 목적·페이지를 초기화하며, 다른 목적을 고르면 첫 페이지로 이동함.
- 테스트 API에서 여러 제품·목적을 제공하고 응답을 지연해 빠르게 전환했을 때, 이전 목적·게시글 응답이 새 선택을 덮어쓰지 않음을 확인함.
- 제품·사용 목적·게시글 조회 실패와 재시도, 각 빈 결과를 구분함. 목적·게시글 조회 실패 중에도 제품 탐색을 유지함.
- 잘못된 제품·목적 코드로 직접 들어오면 안내와 탭을 통해 복구할 수 있음.
- 글쓰기, 댓글이 있는 상세 화면, 목록 복귀와 페이지 이동 확인.
- 추천 흐름의 제품·사용 목적 카드와 다음 버튼을 브라우저에서 확인했다. 공용 `SelectionView`, 추천 화면, 공통 헤더·스타일은 이번 변경에서 수정하지 않았다.
- 위 검증은 로컬 테스트 API로 수행했다.

## 연동 조건

- 확인 시점에 선행 API PR #162(#159)는 아직 열려 있어, 실제 서버 연동은 미검증이다.

- 배포 시 댓글 API와 게시글 목록의 `commentCount`가 먼저 제공되어야 한다.
