# 판매처 가격 비교

쿠팡·제조사·학생복지스토어·당근의 확인한 가격을 모두 최저가에 포함한다.
목록 대표 가격, 가격 정렬, 예산 필터는 같은 최저가를 사용한다.
미확인 가격은 0원이나 추정값으로 등록하지 않는다.

## 가격의 의미

- `priceCondition`: 학생 인증 등 적용 조건. 기존 데이터와 생략한 입력은 기존 일반 판매가 의미를 유지한다.
- `priceBasis`: 판매처가 제시한 가격은 `SELLER_PRICE`, 검수한 매물 중 관측 최저가는 `OBSERVED_LOWEST`다.
- `linkType`: 특정 옵션 구매 페이지는 `PURCHASE`, 제품 검색 페이지는 `SEARCH`다.
- `purchaseUrl`: 기존 API 이름을 유지한 이동 URL이다. `SEARCH`이면 구매 가능한 개별 매물 링크로 표시하지 않는다.
- `externalItemId`: 개별 판매 옵션 ID다. 검색 URL이나 검색어를 ID로 저장하지 않는다.
- `checkedAt`: 가격을 확인한 날짜다. 파일 등록일이나 가격이 변경된 날짜로 대체하지 않는다.

당근은 판교의 동일 사양·미개봉·판매 중 매물에서 확인한 최저가다.
조건에 관측 범위를 기록하고 검색 링크를 제공한다. 검색 시 같은 가격의 매물이 남아 있다는 보장은 아니다.
평균·서울 구별 집계·할인 계산 엔진은 구현하지 않는다.

## 최저가 출처

기존 `product_min_price`의 모든 판매 중 오퍼 최솟값을 유지한다. 학생가·당근가도 포함한다.
선택된 페이지의 제품 ID를 한 번에 조회해 캐시 가격과 일치하는 판매 중 오퍼를 연결한다.
동률이면 가장 작은 오퍼 ID를 선택하며 상세도 가격·ID 순서다.
가격이 일치하는 판매처가 없으면 출처를 비워 두고 다른 가격의 판매처를 대신 붙이지 않는다.
승자 ID 컬럼을 추가하지 않으므로 구버전 가격 갱신도 기존 캐시를 그대로 사용할 수 있다.
가격 등록·변경 마이그레이션에서는 기존 규칙대로 같은 변경에서 최저가를 다시 계산해야 한다.

## API 호환성과 조회

목록의 기존 `minPrice`는 유지하며 `minPriceOffer`에 선택한 판매처의 오퍼 정보를 추가한다.
상세 `offers`의 기존 필드를 유지하고 `id`, `priceCondition`, `priceBasis`, `linkType`을 추가한다.
`minPriceOffer`가 있으면 그 `price`는 목록 `minPrice`와 같고 상세의 첫 오퍼와 같은 동률 기준이다.
가격 또는 일치하는 출처가 없으면 `minPriceOffer`는 null이다. 조건을 임의로 일반가라고 추정하지 않는다.
목록과 출처는 기존 서비스 읽기 트랜잭션에서 조회한다. 스냅숏 일관성은 DB 격리 수준에 따르며
MySQL 기본 REPEATABLE READ를 전제로 한다. 읽기 전용 설정 자체가 격리 수준을 지정하지는 않는다.
출처는 페이지당 최대 한 번 조회하며 가격 없는 페이지에는 추가 조회가 없다.

기존 클라이언트는 추가 필드를 무시할 수 있다. 새 화면은 구버전 서버 응답과 혼재할 때
`minPriceOffer`·추가 오퍼 필드가 없을 수 있음을 처리해야 하며 조건을 추정해서는 안 된다.
9014~9015 화면에서는 목록에 판매처·조건, 상세에 조건·확인일·근거를 표시하고
`SEARCH` 버튼은 ‘당근에서 검색’으로 제공한다. 특정 매물로 즉시 구매할 수 있다고 표시하지 않는다.
화면은 절대 HTTP(S) 주소만 링크로 활성화하며 구버전의 링크 종류 미기록은 ‘판매처 보기’로 표시한다.
확인일은 날짜 문자열 그대로 표시해 브라우저 시간대에 따라 하루가 바뀌지 않도록 한다.
가격 조건이 누락되면 ‘조건 정보 없음’, 확인일이 없으면 ‘확인일 미기록’으로 구별한다.

## 독립 브랜치와 마이그레이션

이 스택은 `develop`의 V1.14에서 시작하며 카탈로그 9001~9007에 의존하지 않는다.
V1.16은 현재 develop에 적용할 수 있는 새 파일이며 기존 카탈로그 V1.15는 변경하지 않는다.
번호를 비웠다고 향후 병합 문제가 해결된 것은 아니다. V1.16을 먼저 적용한 DB에
카탈로그 V1.15가 뒤늦게 합류하면 적용 순서 문제가 생긴다.
공유 DB 적용 전에 병합 순서를 결정하고 이번 스택의 미공유·미적용 파일만 번호를 정리한다.
카탈로그 V1.15가 먼저 합류하면 이 스택을 이후 버전으로 적용하고 빈 DB·기존 DB 업그레이드를 검증한다.
이미 공유 DB에 적용된 파일은 수정하지 않으며 `outOfOrder`로 우회하지 않는다.
개발 검증은 카탈로그가 적용된 DB와 분리된 테스트 DB를 사용한다.

## 실제 데이터

현재 변경은 기능 구현이며 실가격 등록이 아니다. 테스트 가격은 테스트 코드에만 둔다.
기존 프론트는 모든 대표 가격을 일반 판매가로 표시하므로 실제 학생·당근 데이터는
9014~9015 화면 반영 후 적용한다. API 필드 추가만으로 기존 화면의 의미가 바뀌지는 않는다.
제조사 정확 SKU 가격은 미확인이다. ASUS G614PM-TS171W는 공식 사양과 시드 RAM의
차이가 판매자 업그레이드인지 확인해야 하며 이 작업에서 기존 제품 사양을 바꾸지 않는다.
학생복지스토어는 현재 이용 조건과 외부 게시 허용 범위 확인 전 등록을 보류한다.
당근은 사용자가 제공하는 판교 검색 링크와 정확한 미개봉 매물 근거를 검수한 뒤 등록한다.
