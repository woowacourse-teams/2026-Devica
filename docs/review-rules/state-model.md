# 상태 모델

화면 상태를 어떤 값으로 두고, 어떻게 동기화하는지 본다. 원본 값과 파생 값이 섞이거나 한 값이 여러 역할을 맡으면, 특정 조작 순서에서만 드러나는 버그가 생긴다.

Hook 호출 규칙이나 effect 의존성 누락처럼 린터(Biome)가 잡는 것은 보지 않는다.

## STATE-1 사용자 입력을 가공한 값으로 되돌려 쓰지 않는다 · 필수

입력값을 trim 같은 방식으로 가공해 조건에 넣은 뒤, effect가 그 조건값으로 입력칸을 다시 채우면 입력 도중 글자가 사라진다. 예를 들어 끝 공백이 지워져 `apple macbook`이 `applemacbook`이 된다.

- 입력 상태를 다른 상태로 덮어쓰는 effect가 있는지 본다. 되돌려 써야 하는 경우는 "조건 지우기"처럼 입력을 비울 때뿐인지 확인한다.

## STATE-2 여러 경로로 들어오는 화면의 돌아갈 위치를 덮어쓰지 않는다 · 권장

같은 화면에 여러 곳에서 들어올 수 있으면, 돌아갈 위치를 한 값으로 고정해 저장하는 순간 일부 경로가 깨진다. 예를 들어 A 화면에 들어갈 때마다 "뒤로 가면 B"로 덮어쓰면, C에서 들어온 사용자도 뒤로 가기에서 B로 가고, B가 보여줄 데이터가 없으면 빈 화면을 보게 된다.

- 화면 이동 상태를 쓰는 곳마다, 현재 화면이 어디인지에 따라 기존 값을 유지해야 하는 경우가 있는지 본다.
- 진입 경로를 모두 나열해 보고, 각 경로에서 "뒤로"를 눌렀을 때 갈 곳을 따라가 본다.
