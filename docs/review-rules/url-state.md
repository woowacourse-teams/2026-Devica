# 주소 상태

화면이 쓰는 값은 주소의 쿼리에 담는다([ADR 0030](../adr/0030-화면-주소-방식.md)). 주소는 누구나 고칠 수 있고, 공유되고, 외부 서비스로 전송된다. 이 규칙은 주소에서 읽은 값을 믿고 쓰거나, 쓰고 난 값을 주소에 남겨 두는지 본다.

## URL-1 주소에서 읽은 값은 허용 목록으로 검증하고, 잘못된 값은 기본값으로 바꾼다 · 필수

[ADR 0031](../adr/0031-라우팅-라이브러리.md)에서 쿼리 값 검증을 주소를 읽는 쪽이 맡기로 했다. 검증 없이 넘기면 서버가 enum 변환 오류를 돌려주거나, 맞춤 목록이 조건에 맞는 권장안이 없다고 보고 빈 결과를 보여 준다. 필수값이 빠진 주소를 한 화면은 열어 주고 다음 화면은 404로 보내면, 사용자는 첫 화면이 정상이라고 믿었다가 버튼을 누르는 순간 막힌다.

- 주소에서 새로 읽는 값마다 허용 목록이나 형식 검사를 거치는지 본다. `routes.ts`의 `sortOf`·`specOsOf`처럼 모르는 값을 `null`로 바꾸는 함수를 거쳐야 한다. 서버에서 받아야 알 수 있는 값은 목록을 받은 뒤 가리는지 확인한다.
- 화면이 반드시 필요로 하는 값은 화면에 들어올 때 검증하는지 본다. 빠졌으면 API 를 부르거나 결과를 그리지 말고 바로 안내 화면으로 보내야 한다.

## URL-2 한 번 읽고 끝나는 값은 읽은 직후 주소에서 지운다 · 권장

`?internal=1`처럼 브라우저 설정을 바꾸는 일회성 값이 주소에 남으면, 그 주소를 복사해 공유받은 사람도 같은 설정이 걸린다. 설정이 localStorage 에 저장되면 그 뒤 일반 주소로 와도 풀리지 않는다.

- 읽고 나면 더 쓰지 않는 쿼리가 있는지 본다. 있으면 읽은 직후 `history.replaceState`로 그 값만 지우고 나머지 쿼리와 hash 는 남기는지 확인한다.
- 지우기 전에 주소가 바뀔 수 있으면(라우터 초기화, 자동 이동), 먼저 동기적으로 읽어 두는지 본다.
