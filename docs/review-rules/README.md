# 리뷰 규칙

`frontend-review` Skill이 프론트엔드 변경을 리뷰할 때 쓰는 규칙이다. 이 README를 뺀 파일 하나마다 리뷰어가 하나씩 붙는다.

## 규칙을 추가할 때

리뷰에서 같은 지적이 반복되면 규칙으로 만든다. 먼저 어디에 둘지 정한다.

- **코드만 보고 기계적으로 판정할 수 있으면** `frontend/biome.json`의 린트 규칙으로 추가한다. 그러면 매번 LLM이 판단하지 않아도 되고, 결과도 항상 같다. 추가하기 전에 자동 수정이 `safe`인지 확인한다. 동작을 바꿀 수 있는 수정은 `--write`로 적용되지 않아야 한다.
- **동작이나 흐름을 판단해야 하면** 여기에 규칙을 추가한다. 관심사가 기존 파일과 같으면 그 파일에 새 ID로 추가하고, 다르면 파일을 새로 만든다.

기획이나 기술 스택처럼 자주 바뀌는 내용은 넣지 않는다. 특정 화면이나 요구사항이 아니라, 다른 화면에서도 다시 생길 수 있는 문제만 규칙으로 만든다.

## 형식

- 제목은 `## <ID> <규칙 한 줄> · 필수|권장` 형식으로 쓴다. ID는 파일마다 같은 접두사를 쓴다 (`ASYNC-1`, `STATE-1`).
- 본문에는 왜 문제인지와 리뷰어가 무엇을 확인할지를 적는다.
- 필수 항목은 해결하거나 근거를 들어 기각하기 전까지 push를 막는다. 막을 만큼 중요한 것만 필수로 둔다.
