# 비동기 요청

서버 요청의 응답은 늦게 오거나, 순서가 뒤바뀌거나, 실패할 수 있다. 이 규칙은 그런 경우에도 화면이 사용자에게 틀린 정보를 보여주지 않는지 본다.

effect 의존성 누락처럼 린터(Biome)가 잡는 것은 보지 않는다.

## ASYNC-1 늦게 도착한 응답이 새 상태를 덮지 않는다 · 필수

조건을 빠르게 바꾸면 요청이 여러 개 나가고, 응답은 보낸 순서대로 온다는 보장이 없다. 먼저 보낸 요청의 응답이 늦게 오면, 선택한 조건과 다른 결과가 화면에 남는다.

- 요청을 보내는 effect에 정리 함수가 있는지 본다. 정리 함수에서 이전 요청을 무효 처리하거나 취소해야 한다.
- 같은 문제는 목록뿐 아니라 id가 바뀌는 상세 화면에서도 생긴다.

## ASYNC-2 불러오는 중·실패·빈 결과를 구분해 보여준다 · 필수

결과를 `[]`로 시작하거나 실패를 `[]`로 삼키면, 세 상태가 모두 "결과 없음"으로 보인다. 그러면 사용자는 기다려야 할 때나 서버가 실패했을 때도 "조건을 바꾸라"는 틀린 안내를 받는다.

- 아직 받지 못한 상태가 빈 결과와 구분되는지 본다 (`null`, 상태 값 등).
- 실패 시 결과 없음 안내가 아니라 실패 안내가 뜨는지 본다.

## ASYNC-3 요청을 일으키는 조작은 기다리는 동안 잠그고, 실패는 그 화면에서 알린다 · 필수

버튼이 기다리는 동안 잠기지 않으면, 연타할 때마다 요청이 여러 번 나간다. 실패 상태가 버튼이 있는 화면까지 전달되지 않으면, 버튼이 먹통처럼 보인다.

- 대기·실패 상태가 요청을 일으킨 모든 화면에 전달되는지 본다. 같은 요청을 여러 화면에서 일으키면 그 화면들을 모두 확인한다.

## ASYNC-4 로딩 표시는 실제 요청과 함께 끝난다 · 필수

고정 타이머로 로딩 화면을 보여주면, 요청이 느릴 때 로딩이 먼저 끝나 빈 화면이나 틀린 안내가 보인다. 요청을 로딩 화면이 끝난 뒤에 시작하면 이 문제가 항상 생긴다.

- 로딩 표시가 요청이 끝날 때까지 유지되는지 본다. 최소 노출 시간은 둘 수 있지만, 요청보다 먼저 끝나서는 안 된다.

## ASYNC-5 응답이 도착했을 때 사용자가 이미 떠났으면 화면을 옮기지 않는다 · 권장

기다리는 동안 사용자가 다른 화면으로 이동할 수 있다. 응답 처리에서 무조건 화면을 전환하면, 사용자가 원래 화면으로 끌려간다.

- 응답 처리에서 화면을 전환한다면, 전환 전에 현재 화면을 확인하는지 본다.
