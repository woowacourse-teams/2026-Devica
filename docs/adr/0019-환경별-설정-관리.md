# 19. 환경별 설정을 실행 구성 파일이 아니라 프로파일과 서버 환경 변수로 나눈다

- 상태: Accepted
- 날짜: 2026-08-27

## 상황 (조건)

- 개발 서버와 운영 서버가 있고([0018](0018-환경-분리.md), [0017](0017-서버-환경-분리.md)), 두 서버는 같은 배포 번들을 받는다([0014](0014-CD-파이프라인.md), [0015](0015-배포-이미지-전달-방식.md)).
- 실행 구성 파일(compose)에서 환경에 따라 달라져야 하는 값은 활성 프로파일 하나뿐이다. 이미지 태그, DB 계정·비밀번호, DB 이름은 이미 각 서버의 `/opt/app/.env`에서 온다.
- 운영의 스키마 정책이 서버의 `.env`에 `DDL_AUTO=update`로 정의돼 있다.
- [0017](0017-서버-환경-분리.md)의 감수 4번은 "compose 파일을 나누고 `buildspec.yml`과 `scripts/deploy.sh`가 환경을 구분하도록 고쳐야 한다" 를 개선 방향으로 적어두었다.

## 고려한 대안

**1. compose 파일을 환경별로 분리한다**

- 환경별 구성이 파일에 그대로 드러난다.
- 같은 내용이 두 파일에 중복돼 유지 보수가 어렵다.
- 배포 스크립트가 어느 파일을 쓸지 골라야 한다.

**2. 공통 파일에 환경별 파일을 덧씌운다**

- 공통 부분이 한 곳에 있어 중복이 없다.
- 파일 수가 늘어난다.
- 배포 스크립트가 합칠 파일을 골라야 하는 것은 1과 같다.

## 선택: compose 파일은 하나만 두고, 활성 프로파일은 각 서버의 `.env`에서 받는다

compose 파일에는 값을 적지 않고, 실제 값은 서버에서 `.env`로 주입받는다.

**근거**

1. 환경에 따라 달라지는 값이 한 줄뿐이다. 이미지 태그도, DB 계정과 비밀번호도 이미 `.env`에서 오기 때문에, 파일을 늘리면 유지보수 비용만 는다.
2. 배포 스크립트가 환경을 알 필요가 없다. `deploy.sh`가 하는 일(이미지 적재 → 태그 갱신 → 컨테이너 교체)에 환경별로 갈리는 동작이 하나도 없다.
3. "개발에서 먼저 검증한다"는 이점은 브랜치가 이미 보장한다. 코드가 `develop` → `main` 순으로 흐르므로 실행 구성 변경도 반드시 개발 환경을 먼저 거친다.
4. 값이 없을 때 조용히 잘못 뜨는 것을 막을 수 있다. 필수 변수로 선언하면, 프로파일이 없을 때 기본값(`local`)으로 뜨는 대신 컨테이너를 만들기 전에 멈춘다.
5. 스키마 반영 정책은 비밀값이 아니므로 프로파일 파일로 옮긴다. 서버에만 있으면 인스턴스를 다시 만들 때 재현할 수 없다. 운영을 `validate`로 고정하는 것은, `update`로 뜨면 배포가 곧 스키마 변경이 되어 롤백이 성립하지 않기 때문이다.

## 감수하는 것

1. **`dev`와 `prod` 프로파일 파일의 DB 접속 설정 중복**

   현재 8줄이다. 공통을 빼는 방법(`spring.profiles.group` 등)은 "이 설정이 어디서 오는지"를 한 단계 더 추적하게 만든다. 어긋나면 기동 시점에 드러나므로 조용히 썩지는 않는다.

   대응: 공통 부분이 늘어나면 그때 분리한다.

2. **서버에만 존재하는 환경 식별자**

   `SPRING_PROFILES_ACTIVE`는 배포 스크립트가 갱신하지 않으므로, 서버를 새로 만들 때 사람이 한 번 넣어야 한다. 빠뜨리면 첫 배포가 컨테이너를 만들기 전에 멈춘다.

   그리고 어느 서버가 어떤 프로파일로 떠 있는지는 저장소만 봐서는 알 수 없다. 확인하려면 그 서버의 `.env`를 봐야 한다.

3. **운영 스키마 변경의 수동 반영**

   `validate` 고정이므로 엔티티가 바뀐 배포는 스키마를 먼저 반영하지 않으면 기동에 실패한다. 이는 롤백이 성립하게 만들기 위해 의도한 동작이다.

   대응: Flyway 도입 전까지는 수동으로 반영한다.

4. **구성이 갈릴 때 필요한 재검토**

   개발 환경에만 필요한 컨테이너가 생기거나 포트·볼륨 구성이 달라지면 이 선택은 성립하지 않는다. 그때 대안 1이나 2로 옮긴다. 나누는 기준은 값이 아니라 구성이다.
