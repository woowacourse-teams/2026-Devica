# 24. 권장 사양의 CPU 를 cpu 행이 아니라 등급 enum 으로 표현한다

- 상태: Accepted
- 날짜: 2026-09-14

## 상황 (조건)

- 맞춤 질문 답변으로 권장 사양(OS·CPU·메모리·저장 공간)을 계산한다. 이 사양은 화면에 보여주고,
  같은 조건으로 제품을 검색한다.
- 직전까지 권장 CPU 는 `"M 칩"` 같은 표시용 문자열이었다. 비교가 불가능해 검색으로 넘길 수 없었다.
- 제품 검색은 `cpu.score` 하한으로 거른다. 점수는 실제 칩의 벤치마크 측정값이고 `cpu` 테이블에 있다.
- **추천 알고리즘은 확정되지 않았고 교체될 수 있다.** 알고리즘 교체에 있어 확장성 있게 설계하는 것이
  이번 설계의 최우선 가치이다.
- 알고리즘은 정해진 등급 몇 개 중 하나를 골라 조건이 걸릴 때마다 한 칸 위로 옮긴다 — 빌드 대기 경험이
  있으면 한 단계 위, Mac 은 M Pro 에서 멈춘다. 맞춤 질문의 "지금 쓰는 CPU" 선택지가 이미 같은 구분이다
  (Mac `BASIC`·`PRO`·`MAX`, Windows `U`·`P_HS`·`H`·`HX`).
- Windows CPU 는 Intel 과 AMD 가 섞여 있어 제조사를 가로질러 한 줄로 세울 수 없다.

## 고려한 대안

**1. `cpu` 테이블의 행(`Cpu` 엔티티)을 그대로 쓴다**

- 이름과 점수가 한 곳에 있어 중복이 없다.
- 권장 사양이 특정 모델을 지목하게 된다. "이 정도 급"이라는 요구와 의미가 다르다.
- 올릴 다음 칸이 정해지지 않는다. 점수순으로 다음 행을 집으면 카탈로그에 칩이 하나 등록될 때마다
  추천 결과가 바뀐다.
- 알고리즘이 리포지토리를 들어야 해서 단위 테스트가 통합 테스트가 된다.

**2. `cpu` 테이블에 등급 컬럼을 둔다**

- 어떤 칩이 몇 등급인지가 데이터에 있어 점수 임계값을 코드에 두지 않아도 된다.
- 등급은 점수대에 붙인 이름인데, 점수와 등급을 행마다 따로 관리하게 된다.
- 스키마 변경과 시드 정합성 관리가 따라온다.

## 선택: 등급 enum(`CpuTier`)을 두고 검색할 때 점수 하한으로 바꾼다

`CpuTier` 가 OS·표시명·최소 점수를 갖는다. 권장 사양(`LaptopSpec`)은 등급을 담고,
제품 검색은 `cpu.score >= tier.minScore` 로 거른다.

**근거**

1. 알고리즘의 조정 단위가 등급이다. "한 단계 올리기"가 규칙의 전부인데, 등급이 타입이면
   `stepUp()` 으로 그대로 표현된다. `Cpu` 행이면 등급 순서를 따로 만들고 다시 행으로 되돌려야 한다.
2. 알고리즘이 DB 를 타지 않아 교체 비용이 구현체 하나로 유지된다 — 최우선 가치다.
3. 제조사가 여럿인 문제를 등급이 흡수한다. Intel 과 AMD 를 줄 세울 수는 없어도 같은 점수대인지는
   말할 수 있다. 한 등급이 두 제조사를 함께 이름에 담는다(`H` = `고성능 Core Ultra 7 / Ryzen 7`).
4. 권장 사양은 모델 지목이 아니라 요구다. 화면에 `Apple M4` 를 찍으면 사용자가 그 모델만 찾게 된다.
5. 점수대를 등급의 정의로 두면 코드의 임계값은 측정값의 복제가 아니라 우리 분류 기준이 된다.
   배포 없이 바꿀 요구가 없어 컬럼(대안 2)으로 두지 않는다.

## 감수하는 것

1. **점수대가 잠정값이고 카탈로그와 함께 움직인다**

   시드된 두 행(`Apple M4` 21000, `Intel Core Ultra 7 255H` 24000)에만 맞춰 두었고 나머지 다섯
   등급은 추정치다. `cpu.score` 의 기준 벤치마크를 바꾸면 `CpuTier.minScore` 도 따라가야 하는데,
   어긋나도 테스트가 잡지 못하고 검색 결과만 조용히 달라진다.

   대응: 제품 데이터가 쌓이면 실제 분포를 보고 조정한다. `CpuTier` 한 곳만 고치면 된다.

2. **한 등급이 제조사를 가로지르는 근사다**

   AMD 가 Intel 과 다른 점수 곡선을 그리면, 이름은 `HX` 급인 Ryzen 칩이 실제로는 `H` 점수대에
   앉을 수 있다. 제조사별로 등급을 나누려면 질문 선택지와 문구까지 함께 바뀌므로 지금은 감수한다.

3. **질문 선택지와 등급을 이름으로 잇는다**

   `CurrentWindowsCpu.H` 를 `CpuTier.H` 로 잇는 근거는 이름이 같다는 것뿐이라, 선택지를 추가하거나
   이름을 바꾸면 컴파일이 아니라 런타임에 깨진다.

   대응: `CpuTierTest` 가 선택지 enum 의 이름마다 같은 이름의 등급이 있는지 확인한다.

4. **사양 항목 코드가 둘로 갈린다**

   제품은 실제 모델명을 `CPU` 로, 권장 사양은 등급을 `REQUIRED_CPU` 로 내보낸다. 화면 라벨은 둘 다
   "CPU" 지만 클라이언트는 코드 두 개를 알아야 한다. 값의 종류가 실제로 다른데(`Apple M4` 와 `PRO`)
   코드만 같아지면 표면상 통일이 의미상 불일치가 되므로 합치지 않았다.
