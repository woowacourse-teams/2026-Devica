# 32. 제품 이미지는 초기에는 S3에서 직접 제공하고 CloudFront는 필요할 때 도입한다

- 상태: Accepted
- 날짜: 2026-09-30

## 상황 (조건)

- prototype에서 가져온 제품은 20개이고 각각 대응하는 WebP 이미지가 있다. 이미지 20개는 현재 `techcourse-project-2026` 버킷의 `devica/dev/product-images/` 아래에 업로드돼 있다.
- 제품 목록·상세 API는 DB의 `product.image_key`로 이미지 URL을 구성한다. 이미지 키와 이미지 제공 도메인을 분리하면 CDN 도입 시 제품 데이터의 키를 바꾸지 않아도 된다.
- 정식 제품 데이터는 Flyway 시드로 개발 DB에 먼저 등록한다. 초기에는 이미지 수가 적고, CloudFront 배포·권한 설정을 당장 운영할 필요가 있는지 아직 확인되지 않았다.

## 고려한 대안

**1. 이미지를 애플리케이션 정적 파일로 포함한다**

- 애플리케이션 배포만으로 이미지도 함께 배포할 수 있다.
- 이미지를 변경할 때 애플리케이션을 다시 빌드·배포해야 한다.

**2. S3 객체 URL로 직접 제공한다**

- 이미 업로드된 객체를 사용하고 이미지 제공 구성을 단순하게 시작할 수 있다.
- 브라우저가 객체를 받도록 S3 읽기 권한을 관리해야 하고 CDN의 엣지 캐시를 사용하지 않는다.

**3. 지금부터 CloudFront를 S3 앞에 둔다**

- CDN 캐시와 OAC를 이용한 S3 직접 접근 제한을 구성할 수 있다.
- 배포, 원본 경로, 캐시 및 버킷 정책을 이미지 등록과 동시에 설정·검증해야 한다.

## 선택: S3 직접 제공 후 필요할 때 CloudFront 도입

현재 버킷의 WebP를 그대로 사용한다. DB의 `product.image_key`에는 버킷 이름을 제외한 **전체 S3 객체 키**인 `devica/dev/product-images/{prototypeId}/{sha256}.webp`를 저장한다. API는 `app.product-image-base-url`의 버킷 루트 주소와 키를 합쳐 `imageUrl`을 반환한다. 기본 주소는 `https://techcourse-project-2026.s3.ap-northeast-2.amazonaws.com`이고, 배포 환경에서는 `PRODUCT_IMAGE_BASE_URL`로 바꿀 수 있다.

CloudFront가 필요해지면 S3 버킷을 원본으로 두고 Origin Path를 비운 상태에서 기존 키의 접근을 확인한 뒤 이미지 기본 주소를 CloudFront 도메인으로 교체한다. [AWS 문서](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/DownloadDistValuesOrigin.html)에 따르면 Origin Path를 넣으면 S3로 보내는 요청 앞에 그 경로가 추가된다. S3 직접 접근도 차단하려면 [OAC와 버킷 정책](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html)을 별도 작업으로 적용한다.

**근거**

1. 현재 필요한 제품 이미지 20개가 S3에 있어, 이미지 등록과 제품 시드를 검증하는 단계에서 새 배포 계층을 운영하지 않아도 된다.
2. 전체 객체 키와 제공 도메인을 분리했으므로 이후 CloudFront 도입 시 DB의 20개 키와 시드 SQL을 수정하지 않고 주소 설정을 바꿀 수 있다.
3. 초기 이미지 수가 20개인 현재 조건에서는 CloudFront의 캐시 성능·운영 비용의 실제 효과를 확인한 뒤 도입 시점을 정하는 편이 적절하다.

## 감수하는 것

1. **초기에는 S3 URL을 브라우저에 공개해야 한다**

   CloudFront OAC로 S3 직접 접근을 제한하는 구성을 사용하지 않는다.

   대응: 공개 읽기 권한은 제품 이미지 접두사로 한정하고 버킷 정책을 검토한다. 정책 범위의 검증은 객체 응답 확인과 별도로 수행한다.

2. **이미지 제공 도메인을 바꿀 때 경로가 중복될 수 있다**

   `imageKey`가 전체 객체 키이므로 기본 주소나 CloudFront Origin Path에 `devica/dev`를 중복 설정하면 이미지가 깨진다.

   대응: 기본 주소는 도메인 루트로, CloudFront Origin Path는 빈 값으로 유지한다. 변경 전에 20개 키의 접근을 검사하고 목록·상세 API를 확인한다.

3. **S3 직접 제공 중에는 CloudFront의 캐시를 사용하지 않는다**

   이미지 요청량이나 접근 지역이 늘면 응답 지연·전송 비용을 다시 평가해야 한다.

   대응: 실제 트래픽과 이미지 요청 패턴을 보고 CloudFront 도입을 별도 작업으로 결정한다.
