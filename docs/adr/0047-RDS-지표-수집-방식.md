# 47. RDS 지표를 Alloy가 CloudWatch에서 읽어 Grafana Cloud로 보낸다

- 상태: Accepted
- 날짜: 2026-10-21

## 상황 (조건)

- dev·prod DB가 RDS로 옮겨 가면서 DB 상태가 호스트 지표에서 빠졌다([ADR 0038](0038-DB-RDS-이전.md)).
- RDS 지표는 CloudWatch에만 있다.
- 앱·호스트 지표와 알림 규칙은 모두 Grafana Cloud에 모여 있다.
- 우아한테크코스의 정책상 IAM 서비스를 사용할 수 없다. 따라서 역할이나 사용자, 정책을 새로 만들 수 없다.
- prod EC2 인스턴스 역할에는 이미 CloudWatch 지표 조회 권한(`ListMetrics`, `GetMetricData`)이 있다. 서버에서 직접 조회해 확인했다.
- 각 서버에 Alloy가 떠 있고, 설정은 `monitoring/config.alloy`로 배포된다([ADR 0035](0035-로그-수집기.md)).

## 고려한 대안

**1. Grafana Cloud에 CloudWatch 데이터 소스 연결**

- Grafana Cloud가 CloudWatch를 직접 조회해, 서버 배포 없이 화면에서 설정하고 수집이 서버 상태와 무관하다.
- Grafana가 맡을 IAM 역할이나 액세스 키를 AWS 계정에 새로 만들어야 한다.

## 선택: Alloy의 `prometheus.exporter.cloudwatch`

각 서버의 Alloy가 자기 환경의 RDS(`db-devica-<env>`) 지표를 CloudWatch에서 읽어 Grafana Cloud Prometheus로 보낸다.

**근거**

1. IAM을 만들 수 없어 대안 1은 쓸 수 없다.
2. 지표가 기존 Prometheus에 들어가, 대시보드와 알림 규칙, 수신처를 지금 구성 그대로 쓴다.

## 감수하는 것

1. **앱 서버가 죽으면 RDS 지표도 끊긴다**

   RDS 지표를 앱 서버의 Alloy가 가져오므로, 서버나 Alloy가 멈추면 DB가 정상이어도 지표가 비어 보인다.

   대응: 그 상황은 App Down과 Synthetics가 먼저 알린다. DB 상태는 RDS 콘솔에서 확인한다.

2. **인스턴스 역할 권한에 기대고 있다**

   공용 계정 운영진이 인스턴스 역할을 바꾸면 RDS 지표만 조용히 끊긴다. 팀이 권한을 직접 관리할 수 없다.

   대응: 대시보드의 RDS 행이 비면 서버에서 CloudWatch 조회 권한부터 확인한다.
