# 49. 제품 추천 개선 루프를 OS 의 예약 실행 기능으로 에이전트 CLI 로 실행한다

- 상태: Accepted
- 날짜: 2026-10-27

## 상황 (조건)

- 제품 추천 개선 루프의 세 구성 요소(Metric Collector, Feedback Analyzer, Recommendation Improver)는 에이전트가 지시문(`recommendation-improvement/<구성 요소>/prompt.md`)을 따라 실행한다.
- 에이전트 실행에 별도 API 비용은 쓰지 않는다. 팀원의 개인 구독 계정으로 실행한다
- 처음에는 팀원 PC 의 데스크톱 LLM 앱 예약 작업으로 실행하기로 했다([#248](https://github.com/woowacourse-teams/2026-Devica/issues/248)).
- 지시문은 PC 의 레포 clone, 레포 멤버 계정으로 로그인한 `gh`, 개발·운영 서버의 제품 추천 API 를 쓰고, Recommendation Improver 는 Docker 도 쓴다.
- 세 구성 요소는 하루 한 번 또는 몇 시간마다, 사람이 지켜보지 않아도 정해진 주기로 실행되어야 한다.
- Feedback Analyzer 는 외부 사용자가 쓴 피드백 이슈 본문을 읽는다.
- 2026-10-27 Metric Collector 를 데스크톱 LLM 앱 예약 작업으로 처음 실행했다. 앱은 로컬 셸이 아니라 앱이 따로 띄운 격리된 실행 환경에서 명령을 실행했고, 그 환경에서는 위 자원에 접근할 수 없었다([#269](https://github.com/woowacourse-teams/2026-Devica/issues/269)).
  - 연결한 레포 폴더가 셸에서 열리지 않았다.
  - `gh` 가 없거나 로그인되어 있지 않았다.
  - 운영 API 요청이 프록시에서 403 으로 막혔다.
- 팀원마다 쓰는 에이전트가 다르다.(Claude Code, Codex)

## 고려한 대안

**1. 데스크톱 LLM 앱 예약 작업**

- 앱 화면에서 작업을 등록하고, 실행 결과를 대화로 볼 수 있다.
- 명령이 앱이 띄운 격리된 실행 환경에서 실행되어, 그 환경이 열어 준 폴더·네트워크·프로그램만 쓸 수 있다.

**2. GitHub Actions 예약 실행**

- PC 가 꺼져 있어도 돈다.
- 에이전트를 부르려면 API 키가 필요하다. 개인 구독 계정은 CI 에서 쓸 수 없다.

**3. 에이전트 세션 안의 예약 실행**

- 열어 둔 세션에서 주기 작업을 걸면 되어 따로 설정할 것이 없다.
- 세션을 닫으면 멈춘다.

## 선택: OS 의 예약 실행 기능으로 에이전트 CLI 를 주기마다 실행

예약 등록과 에이전트 호출을 나눈다.

**근거**

1. 에이전트 CLI 는 PC 의 셸에서 내 계정으로 실행되어, PC 에 설정한 레포·`gh` 로그인·서버 접속·Docker 를 그대로 쓴다.
2. 개인 구독 계정으로 로그인한 CLI 를 쓰므로 API 비용이 들지 않는다.
3. 예약 등록이 에이전트에 독립적이기 때문에, 다른 에이전트나 Bedrock 으로 옮길 때 에이전트 호출만 바꾸면 된다.
4. OS 의 예약 실행 기능은 터미널이나 앱을 켜 두지 않아도 PC 가 켜져 있고 로그인되어 있으면 실행된다.

## 감수하는 것

1. **예약 설정이 레포 밖, 각자의 PC 에 있다**

   예약 설정은 OS 에 등록되어 각자의 PC 에 있다. 레포를 고쳐도 PC 의 설정은 바뀌지 않는다.

   대응: 예약을 등록하는 스크립트를 레포에 두고, README 의 등록 절차에서 그 스크립트를 실행한다. 지시문은 지금처럼 실행할 때마다 `origin/develop` 에서 읽어, 지시문을 바꿔도 다시 등록하지 않는다.

2. **실행 중에 권한을 물어볼 수 없다**

   비대화 실행이라, 미리 허용하지 않은 명령은 실행되지 못한다. 에이전트가 외부 사용자가 쓴 피드백 이슈 본문을 읽으므로 셸 전체를 허용하지 않고 지시문에 필요한 명령만 허용한다. 그래서 지시문의 여러 줄짜리 명령은 막히고, 에이전트가 단순한 명령으로 나눠 대신 실행한다. 이때 6시간 넘게 남은 잠금을 지우는 검사가 빠질 수 있다.

   대응: 구성 요소마다 허용할 도구를 `run.sh` 에 두고, 막힌 명령은 실행 로그에 남긴다. 남은 잠금은 README 의 문제 해결대로 지운다. 정해진 절차를 프로그램으로 옮기면 이 제약은 사라진다.

3. **에이전트가 허용한 명령으로 레포와 GitHub 데이터를 바꿀 수 있다**

   허용 목록은 에이전트의 파일 편집 기능만 제한한다. 허용한 `python3`·`git`·`gh` 로는 상태 디렉터리 밖의 파일을 쓰거나 GitHub 의 이슈·PR 을 바꿀 수 있다. 에이전트가 피드백 이슈 본문에 숨은 지시를 따르면 그렇게 될 수 있다.

   대응: 구성 요소마다 전용 clone 에서 실행해, 평소 작업하는 clone 이 바뀔 가능성을 줄인다. OS 샌드박스로 막지는 않는다. 정해진 절차를 프로그램으로 옮기고 LLM 은 도구 없이 판단만 하게 하면, 이 위험은 잘못된 판단으로 줄어든다. 판단으로 바뀌는 정의서는 PR 리뷰를 거친다.

4. **지금 구현은 macOS 와 Claude Code 에서만 동작한다**

   예약 등록은 launchd 를 쓰고, 에이전트 호출은 권한 규칙·실행 옵션·출력 형식까지 Claude Code 에 의존한다. 다른 OS 나 에이전트를 쓰는 팀원은 이 구현을 그대로 쓸 수 없다.

   대응: 다른 OS·에이전트에서는 README 의 "다른 방법으로 등록하기"대로 지시문을 직접 등록한다. 에이전트 호출을 에이전트마다 만들지는 않는다.
