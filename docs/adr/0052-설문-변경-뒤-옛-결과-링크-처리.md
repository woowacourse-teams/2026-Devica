# 52. 설문이 바뀐 뒤의 옛 결과 링크는 서버가 정의서의 지운 코드 목록으로 바꿔 읽는다

- 상태: Accepted
- 날짜: 2026-11-05

## 상황 (조건)

- 결과 화면 주소는 고른 답을 `질문 코드=선택지 코드` 로 담는다. 사용자는 이 주소를 저장하거나 공유하고, 제품 추천 의견 이슈에도 이 주소가 남는다.
- 서버는 지금 설문에 없는 코드를 받으면 결과를 내지 않고 거부하며, 화면은 "다시 답해 주세요"만 보인다.
- 제품 추천 개선 루프([0049](0049-제품-추천-개선-루프-실행-방식.md))가 질문과 선택지를 더하는 것뿐 아니라 고치고, 합치고, 지우게 된다(#344). 그때마다 지운 코드가 든 옛 링크가 열리지 않는다.
- 루프의 Feedback Analyzer 는 의견 이슈의 결과 주소로 그 사용자의 결과를 다시 계산한다. 주소가 열리지 않으면 그 의견은 근거에서 빠진다.

## 고려한 대안

**1. 옛 링크가 열리지 않는 것을 감수한다**

- 서버와 화면을 고치지 않아도 된다.
- 설문을 고칠 때마다 저장·공유한 링크와 의견 이슈의 주소가 열리지 않는다. 지운 것을 되돌려도 그 사이에 열리지 않게 된 링크는 다시 열리지 않는다.

## 선택: 정의서의 `survey.retired` 에 지운 코드를 읽는 방법을 적고, 서버가 결과를 계산하기 전에 바꿔 읽는다

지운 질문·선택지 코드마다 지금 코드로 바꿔 읽거나(`to`), 그 답을 버리는(`drop`) 줄을 남긴다. 규칙이 바뀌어 옛 답이 맞지 않는 질문은 `dropInvalid` 로 그 답을 버린다. 바꿔 읽은 답이 하나라도 있으면 결과 응답에 `answersOutdated` 를 담고, 화면은 결과 위에 알리고 다시 답하게 한다.

**근거**

1. 개선 루프가 설문을 고쳐도 옛 링크와 의견 이슈의 주소가 계속 열리고, 지운 것을 되돌려도 링크가 열리지 않게 되는 일이 없다.
2. 바꿔 읽는 방법을 설문을 고치는 같은 PR 의 정의서에 적으므로, 리뷰어가 변경과 그 영향을 한곳에서 본다.

## 감수하는 것

1. **바꿔 읽은 결과는 처음 본 결과와 다를 수 있다**

   지운 답은 빠지고, 합친 선택지는 남는 선택지의 규칙으로 계산된다. 규칙도 그 사이에 바뀌었을 수 있다.

   대응: 바꿔 읽은 결과에는 결과 위에 안내와 "다시 답하기" 버튼을 둔다.

2. **지운 코드 목록은 줄기만 한다**

   지운 코드를 다른 뜻으로 다시 쓰면 옛 링크가 오류 없이 다른 뜻으로 열린다. 그래서 줄을 지우지 않고, 지운 코드는 다시 쓰지 않는다.

   대응: 한 번 지울 때 옛 코드마다 한 줄이라, 네 사용 목적의 질문·선택지를 모두 한 번씩 지워도 수백 줄 안이다.

3. **쪼갠 선택지는 옛 답을 살리지 못한다**

   하나를 둘로 나누면 옛 답이 어느 쪽인지 알 수 없어 버린다.

   대응: 버린 답이 있으면 1 의 안내가 뜬다.

4. **같은 변환 규칙을 서버와 개선 루프 스크립트가 각각 구현한다**

   개선 루프는 서버를 부르지 않고 정의서로 영향 범위를 계산하므로, 변환 규칙이 Java 와 Python 두 곳에 있다.

   대응: 두 구현이 같은 변환 사례표(`src/test/resources/recommendation/retired-cases.json`)로 테스트한다.
