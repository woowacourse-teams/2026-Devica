# 33. 로그 형식으로 ECS(Elastic Common Schema)를 사용한다

- 상태: Accepted
- 날짜: 2026-09-30

## 상황 (조건)

- 애플리케이션은 Spring Boot 4.1.0([ADR 0002](0002-프레임워크.md))이며, 구조화 로그 형식으로 ECS, Logstash, GELF를 기본 지원한다.
- 로그는 필드 조건으로 조회하고, 예외 발생 같은 알림 조건으로도 쓰인다.
- 서버에서 애플리케이션은 Docker 컨테이너로 실행된다([ADR 0006](0006-실행-환경.md)). Docker 는 컨테이너의 표준 출력을 로그로 모으므로, 로그는 파일이 아니라 표준 출력(stdout)으로 남긴다.
- `env`, `app` 레이블은 수집기(Alloy)가 붙인다.

## 고려한 대안

**1. Logstash 형식**

- 필드 이름이 `level`처럼 짧고 평평해, 조회 쿼리가 간단하다.
- 예외 정보가 스택 트레이스 문자열 하나에 담겨, 예외 종류로 조회하거나 알림을 걸려면 문자열을 검색해야 한다.

**2. GELF**

- Spring Boot 설정만으로 적용할 수 있다.
- 로그 레벨이 숫자로 표기되고 추가 필드에 `_` 접두어가 붙어, 조회 조건이 직관적이지 않다.

**3. 직접 정의한 형식**

- 필요한 필드만 원하는 이름으로 구성할 수 있다.
- 형식을 만드는 코드를 작성·유지해야 하고, 필드 이름을 처음부터 정해야 한다.

## 선택: ECS

Spring Boot의 기본 ECS 출력에 `trace.id`와 요청 정보를 추가한다. 서비스 이름 등 레이블과 겹치는 필드는 출력하지 않는다.

**근거**

1. Spring Boot 설정 한 줄로 적용되어, 형식을 만드는 코드가 필요 없다.
2. 예외 종류가 `error.type` 필드로 분리되어, 예외 종류별 조회와 알림을 필드 조건으로 걸 수 있다.
3. HTTP 요청 정보 등의 필드 이름이 표준으로 정해져 있어, 이름을 새로 정할 필요가 적다.

## 감수하는 것

1. **필드 이름이 길어 쿼리가 장황해진다**

   `log.level`처럼 점으로 묶인 이름을 쓰며, 로그 저장소인 Loki의 LogQL에서는 `log_level`처럼 밑줄로 바뀌어 참조된다.

   대응: 자주 쓰는 쿼리는 Grafana에 저장해 재사용한다.

2. **레이블과 겹치는 필드가 기본으로 출력된다**

   ECS는 `service.name`을 기본으로 포함해, Alloy가 붙이는 `app` 레이블과 기준이 둘이 될 수 있다.

   대응: 설정에서 해당 필드를 출력하지 않도록 제외한다.
