# 30. 화면 전환을 상태에서 경로 주소로 바꾼다

- 상태: Accepted
- 날짜: 2026-09-30

## 상황 (조건)

- 지금은 상태만 바꿔 화면을 전환해 주소가 `/` 하나다. `/?view=products`와 `/?view=faq`만 쿼리로 시작 화면을 정한다.
- 새로고침, 뒤로 가기, 링크 공유가 화면 단위로 동작해야 한다.
- 결과와 목록의 주소에 사용 목적, 답변, OS, 정렬·검색 조건을 담기로 했다.
- 프론트엔드는 Vercel에 배포한다([0026](0026-프론트엔드-배포처.md)).
- 배포된 사이트는 저장소에 없는 경로(`/products`)에 404를 돌려준다.
- `/api` 요청은 Vercel 대시보드의 Routing Rules로 백엔드에 넘긴다([0027](0027-API-요청-연결-방식.md)).
- 로컬 Vite 개발 서버는 없는 경로 요청에 `index.html`을 돌려준다.

## 고려한 대안

**1. 쿼리 주소 (`/?view=product&id=12`)**

- 요청 경로가 늘 `/`라서 fallback 규칙 없이도 새로고침과 공유 링크가 404 없이 열린다.
- 화면을 가리키는 값과 화면이 쓰는 값이 같은 쿼리에 섞인다.
- 라우터 라이브러리는 경로를 보고 보여줄 화면을 정한다. 쿼리로 화면을 정하려면 이 처리를 직접 구현해야 한다.

**2. 해시 주소 (`/#/products/12`)**

- `#` 뒤는 서버로 보내지지 않아 fallback 규칙 없이도 새로고침과 공유 링크가 404 없이 열린다.
- 모든 주소에 `#`이 들어가고, 페이지 안 위치로 이동하는 앵커와 같은 자리를 쓴다.
- 서버 접속 로그에는 모든 요청이 `/`로 남아 화면을 구분할 수 없다.

## 선택: 경로 주소

화면은 경로(`/products/12`)로, 화면이 쓰는 값은 쿼리로 나타낸다. 파일이 없고 `/api`로 시작하지 않는 요청에는 `index.html`을 돌려주는 rewrite 규칙(fallback)을 둔다.

**근거**

1. 화면을 가리키는 값은 경로에, 결과·목록이 쓰는 값은 쿼리에 들어가 서로 섞이지 않는다.
2. 라우터 라이브러리의 경로 매칭을 그대로 쓰면 되기 때문에, 주소를 보고 화면을 정하는 코드를 직접 구현할 필요가 없다.
3. 규칙이 저장소에 있어 코드 리뷰를 거치고 변경 이력이 커밋으로 남는다. 환경마다 바뀌는 값이 없어 대시보드에 둘 이유가 없다.
4. 공유되는 주소가 `#/` 없이 일반 웹 주소 모양(`/products/12`)이다.

## 감수하는 것

1. **라우팅 규칙이 두 곳에 나뉜다**

   `/api` 규칙은 대시보드에, fallback 규칙은 `vercel.json`에 있다.

   대응: [프론트엔드 배포 가이드](../프론트엔드_배포_가이드.md)에 두 규칙을 함께 적는다.

2. **fallback 이 깨져도 로컬에서는 드러나지 않는다**

   개발 서버는 규칙 없이도 `index.html`을 돌려주므로, 규칙이 잘못되면 배포한 뒤에야 새로고침과 공유 링크가 404가 된다.

   대응: Preview 배포에서 깊은 경로의 새로고침과 `/api` 응답을 확인한다.

3. **없는 주소도 200으로 응답한다**

   fallback 이 모든 경로에 `index.html`을 돌려주므로, 없는 경로와 없는 제품은 서버가 아니라 앱이 가려내 안내해야 한다.

4. **기존 `?view=` 링크를 새 주소로 넘겨야 한다**

   이미 퍼진 링크가 계속 열리도록 앱이 옛 주소를 읽어 새 경로로 바꿔 준다.
