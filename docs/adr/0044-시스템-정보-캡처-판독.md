# 44. 시스템 정보 캡처를 브라우저에서 tesseract.js 로 읽는다

- 상태: Accepted
- 날짜: 2026-10-16

## 상황 (조건)

- 현재 사양 화면에서 사용자는 OS, 프로세서, 메모리, 저장 공간을 직접 고른다.
- 프로세서는 모델명이 아니라 "Core Ultra 7 255H급"처럼 등급으로 고른다.
- 이 네 값은 Mac의 "설정 > 일반 > 정보" 화면과 Windows의 "설정 > 시스템 > 정보" 화면에 모두 나온다.
- 이 정보 화면은 OS가 만든 화면이라 항목 이름과 배치가 사용자마다 달라지지 않는다.
- 같은 화면에는 사양 말고도 일련번호, 기기 이름, 계정 이름 같은 개인 정보가 함께 찍힌다.
- 팀은 외부 유료 API를 가능하면 쓰지 않는다.

## 고려한 대안

**1. 서버에서 비전 모델(Claude API 등)로 읽기**

- 글자를 잘못 읽는 일이 적고, 모델명에서 세대까지 고려해 등급을 판단할 수 있다.
- 이미지를 받는 백엔드 API, API 키 관리, 호출마다 드는 비용이 생긴다.
- 캡처가 외부 서비스로 전송된다.

**2. 시스템 정보 텍스트를 붙여넣게 하기**

- 글자 인식 오류가 없고 의존성이 늘지 않는다.
- Windows 정보 화면에는 복사 버튼이 있지만 Mac 정보 화면에는 없다.
- 사용자가 직접 복사·붙여넣기를 해야한다.

## 선택: 브라우저에서 tesseract.js 로 읽기

**근거**

1. 이미지를 브라우저 밖으로 보내지 않아 캡처화면의 일련번호와 기기 이름을 보호할 수 있다.
2. 외부 유료 API 없이 오픈 소스 라이브러리만으로 읽을 수 있다.
3. 정보 화면의 형식이 정해져 있어 키워드와 규칙으로 값을 찾을 수 있다. Mac과 Windows 10·11의 한국어·영어 캡처로 확인했다.

**버전: 7.0.0**

도입 시점의 최신 버전이다.

## 감수하는 것

1. **글자를 잘못 읽는다**

   tesseract.js 는 어떤 언어의 글자를 읽을지 언어 설정으로 정한다. 한국어와 영어를 함께 읽게 하면 "메모리" 같은 한글 항목 이름은 잘 읽지만 "16GB"를 "1668"로 읽는다. 영어만 읽게 하면 반대로 숫자와 단위는 맞게 읽지만 한글 항목 이름을 알아보지 못한다. 또 글자가 작으면 "2.98 GB"를 "298 GB"로 읽는다.

   대응:

   - 같은 캡처를 한국어+영어 설정과 영어 설정으로 한 번씩 읽고, 같은 줄의 결과를 나란히 붙인다. 그러면 한 줄 안에서 항목 이름은 한국어+영어 결과로, 값은 영어 결과로 찾을 수 있다.
   - 작은 캡처는 3배로 키워 읽는다. 그래도 메모리가 128GB를 넘게 읽히면 소수점을 놓친 것으로 보고 비운다.
   - 못 읽은 칸은 비워 사용자가 직접 고르게 한다.

2. **읽는 데 10~20초가 걸린다**

   이미지를 키우고 두 번 읽기 때문이다.

   대응: 읽는 동안 버튼을 잠그고 진행 중임을 알린다.

3. **처음 쓸 때 엔진과 언어 데이터를 CDN에서 받는다**

   언어 데이터만 압축 전 약 7MB(영어 5.2MB, 한국어 2.2MB)이고, jsDelivr에서 받는다. CDN에 접근할 수 없으면 캡처 채우기가 실패한다.

   대응: 실패하면 직접 고르라고 안내한다. 받은 데이터는 브라우저에 저장되어 다음부터 다시 받지 않는다.

4. **Windows 프로세서 등급을 모델명 접미사로만 판단한다**

   U·H·HX 같은 접미사로 등급을 정하므로, 세대가 다른 같은 접미사의 칩(8세대 i7 H와 Core Ultra 9 H)을 구분하지 못한다. 노트북용이 아닌 칩(Xeon 등)은 비운다.

5. **정보 화면의 형식이 바뀌면 규칙을 고쳐야 한다**

   대응: 실제 캡처의 OCR 결과를 테스트로 남겨 규칙을 바꿀 때 기존 화면이 깨지는지 확인한다.
