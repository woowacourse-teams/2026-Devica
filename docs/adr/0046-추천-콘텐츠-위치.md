# 46. 추천 질문과 판단 규칙을 사용 목적별 YAML 파일에 둔다

- 상태: Accepted
- 날짜: 2026-10-19

## 상황 (조건)

- 제품 추천은 설문 답변에 가중치로 점수를 매겨, 제품 유형에 맞는 추천 결과와 근거 문장을 보여준다.
- 사용자 피드백으로 질문 문구와 가중치·근거 문장을 자주 고쳐야 하지만, 고치지 못하고 있다.
- 이 내용이 여러 곳에 나뉘어 있어, 하나를 바꿔도 여러 곳을 함께 고쳐야 한다.
- 그래서 자주 고치는 질문 문구와 가중치·근거 문장을 파일 한 곳에 모으기로 했다.
- 반면 점수를 추천 결과로 바꾸는 규칙은 드물게 바뀐다.
- snakeyaml이 Spring Boot starter에 이미 들어 있다.

## 고려한 대안

추천 콘텐츠를 네 항목으로 나눠, 항목마다 어디에 둘지를 비교한다.

| 항목           | 내용                                                               |
|--------------|------------------------------------------------------------------|
| 질문 문구        | 질문·선택지의 제목과 설명                                                   |
| 화면 묶음        | 어떤 질문을 어느 단계(화면)에 함께 보여줄지                                        |
| 판단 규칙        | 질문을 보여줄 조건, 답변에 따른 가중치와 근거 문장, 답변에서 사용자 조건(선호 OS 등)을 정하는 규칙      |
| 사용 목적별 점수 해석 규칙 | 판단 규칙이 낸 점수를 추천 결과로 바꾸는 규칙. 백엔드 개발은 점수 구간, 라인업, 제약, 결과 문장 |

**1. 사용 목적별 점수 해석 규칙도 파일에 둔다**

- 추천 콘텐츠를 모두 파일 하나에서 관리할 수 있다.
- 규칙이 바뀌는 빈도가 낮다.
- 파일을 불러오고 내용을 검사하는 코드를 새로 만들어야 한다.

**2. 질문 문구는 DB에 둔다**

- 지금의 테이블과 시드를 그대로 쓸 수 있다.
- 질문 문구와 판단 규칙이 나뉘어, 질문 하나를 고칠 때 파일과 마이그레이션을 함께 바꿔야 한다.

**3. 화면 묶음은 프론트에 둔다**

- 서버 응답 형식을 바꾸지 않아 프론트를 고치지 않아도 된다.
- 프론트가 질문 코드를 하드코딩해, 질문을 바꿀 때마다 프론트도 고쳐야 한다.

## 선택: 질문 문구·화면 묶음·판단 규칙은 사용 목적별 YAML, 사용 목적별 점수 해석 규칙은 코드

| 항목           | 선택           | 기각한 위치 |
|--------------|--------------|--------|
| 질문 문구        | 파일           | DB     |
| 화면 묶음        | 파일 (서버가 내려줌) | 프론트    |
| 판단 규칙        | 파일           | -      |
| 사용 목적별 점수 해석 규칙 | 코드           | 파일     |

사용 목적마다 `recommendation/purposes/<사용 목적 코드>.yml` 파일 하나에 둔다. 서버가 화면 묶음을 `survey.steps[]`로 내려주고, DB의 `question`·`question_option`과 프론트 `SCREEN_SPECS`는 지운다. 백엔드 개발의 점수 해석 규칙은 `BackendDevelopmentRecommender`에 둔다.

**근거**

1. 질문 문구와 판단 규칙은 자주, 그리고 함께 바뀐다.
2. 사용 목적별 점수 해석 규칙은 드물게 바뀌어, 파일로 옮겨 얻는 것이 적다.
3. 서버가 화면 묶음을 내려줘야 프론트가 질문 코드를 하드코딩하지 않는다.

**형식: YAML**

주석을 달 수 있고 한국어 문장에 따옴표가 필요 없으며, 질문이나 규칙을 추가해도 diff가 한 줄이다. Spring Boot starter에 든 snakeyaml로 읽어 새 의존성이 없다.

## 감수하는 것

1. **이름 오류를 컴파일이 아니라 서버 시작에서 잡는다**

   파일에 질문·선택지 코드를 잘못 적어도 IDE가 알려주지 않는다.

   대응: 서버가 시작할 때 파일 내용을 검사해, 틀리면 서버가 뜨지 않는다.

2. **질문을 보여줄 조건은 "한 질문에서 특정 선택지 중 하나를 골랐다"만 쓸 수 있다**

   질문을 보여줄지는 프론트가 판단하므로, 조건을 조합하려면 프론트에도 조건 평가기가 필요하다.

   대응: 조합이 필요해지면 프론트 평가기와 함께 넓힌다.

3. **콘텐츠가 바뀌면 이전 답변이 담긴 링크가 깨질 수 있다**

   결과 화면 주소에 답변이 담겨 있어, 질문이나 선택지를 지우면 예전 링크를 서버가 거부한다.

   대응: 프론트가 "질문이 바뀌어 다시 답해야 해요"와 설문 시작 링크를 보여준다.

4. **전환하는 동안 문구가 두 곳에 있다**

   설문 API와 프론트가 파일을 쓰기 전까지 질문 문구가 YAML과 DB 시드에 함께 있다.

   대응: 설문 API를 파일로 옮긴 뒤 `question`·`question_option` 테이블과 시드를 지운다.
