# 6. 실행 환경으로 Docker Compose를 사용한다

- 상태: Accepted
- 날짜: 2026-08-17

## 상황 (조건)

- 팀원의 로컬 OS가 Windows와 macOS로 나뉘어 있다. MySQL은 OS에 따라 기본 설정이 달라지며, 특히 테이블명의 대소문자 구분 여부가 다르다. 로컬에 직접 설치하면 팀원마다 서로 다른 환경에서 개발하게 된다.
- 팀원 전원이 Docker 이미지를 빌드하고 실행해본 경험이 있다. 다만 일부는 Compose에 익숙하지 않다.
- 1개월이라는 기간에서 환경 문제로 발생하는 시간 손실은 그대로 검증 시간의 손실이 된다.

## 고려한 대안

실질적으로 검토한 대안은 없다.

각자 로컬에 직접 설치하면 별도 도구 없이 바로 사용할 수 있으나, OS가 혼재된 상황에서는 팀원 간 환경 차이가 그대로 드러난다. 그 비용이 더 크다고 판단해 후보로 올리지 않았다.

## 선택: Docker / Docker Compose

**근거**

1. 컨테이너 이미지로 DB를 실행하면 OS와 무관하게 같은 환경이 구성된다. 로컬 OS가 달라도 동일한 설정의 MySQL을 사용하므로, 대소문자 구분 같은 OS별 차이가 발생하지 않는다.
2. 개발 환경에서는 로컬 실행용 DB와 테스트용 DB를 함께 띄워야 한다. Compose를 쓰면 두 컨테이너의 설정을 하나의 파일에 정의하고 명령 한 번으로 관리할 수 있다.
3. 설정이 파일로 저장소에 포함되므로, 포트·계정·문자셋 같은 값이 바뀌어도 팀원 전체에 자연스럽게 전파된다. 실행 명령을 각자 관리하는 방식에서는 이런 전파가 보장되지 않는다.

## 감수하는 것

1. **Compose에 익숙하지 않은 팀원이 있다**

   컨테이너 구성이나 설정을 바꿔야 할 때 특정 팀원에게 의존하게 될 수 있다. 다만 개발 중 Compose 파일을 수정할 일이 잦지 않고 실행 자체는 명령 하나로 끝나므로, 일상적인 사용에는 부담이 없다고 판단했다.
