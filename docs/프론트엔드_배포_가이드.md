# 프론트엔드 배포 가이드

**Vercel에 올린 프론트엔드를 다룰 때 보는 문서다.** 백엔드 서버는 [백엔드 배포 가이드](백엔드_배포_가이드.md)에서 다룬다.

---

## 1. 배포는 어떻게 이뤄지나

**손으로 할 일은 없다.** `develop`에 push하면 Vercel이 빌드해서 배포까지 끝낸다.

| 항목             | 값                              |
|----------------|--------------------------------|
| 계정             | 팀 공용 구글 계정                     |
| 프로젝트           | `2026-devica`                  |
| 주소             | https://2026-devica.vercel.app |
| 배포 브랜치         | `develop`                      |
| Root Directory | `frontend`                     |
| 환경 변수          | 없음                             |

모노레포라서 Root Directory를 `frontend`로 지정해 두었다. 빌드 설정은 Vite 자동 감지 기본값 그대로다.

**지금은 배포 환경이 하나다.** 백엔드처럼 개발과 운영을 나눌지는 아직 정하지 않았고, 별도 ADR로 남긴다..

---

## 2. API 연결

**API 주소를 환경 변수로 넣지 않는다.** 흔히 백엔드 주소를 `VITE_API_BASE_URL` 같은 환경 변수로 빌드에 넣고, 브라우저가 그 주소를 직접 호출한다. 여기서는 이 값을 비워 둔다. 코드는
`/api/...`처럼 상대 경로로 호출하고, 그 요청을 백엔드로 넘기는 일은 Vercel의 rewrite가 맡는다. 이렇게 정한 이유는 [ADR 0027](adr/0027-API-요청-연결-방식.md)에 있다.

그래서 백엔드 주소는 코드나 빌드가 아니라 Vercel 대시보드의 **CDN → Routing Rules**에 있다. 저장소에 없으므로 코드만 봐서는 요청이 어디로 가는지 알 수 없다.

| 이름          | 모드    | Source        | 동작      | Destination                      |
|-------------|-------|---------------|---------|----------------------------------|
| `api-proxy` | Regex | `^/api/(.*)$` | Rewrite | `http://dev.devica.co.kr/api/$1` |

https://2026-devica.vercel.app/api/product-categories 를 열어 JSON 응답이 오면 연결된 것이다.

### 백엔드를 바꿀 때

지금은 개발 서버를 임시로 연결해 두었다. 연결 대상을 바꿀 때는 규칙의 Destination 주소만 바꾸고 Publish한다. 코드와 빌드는 건드리지 않는다.

---

## 3. 주의사항

**설정을 바꾸기 전에 확인한다.**

| 설정               | 지킬 것                                                 | 어기면                                   |
|------------------|------------------------------------------------------|---------------------------------------|
| Root Directory   | `frontend`로 둔다                                       | 저장소 루트에서 `package.json`을 찾다가 빌드에 실패한다 |
| 배포 브랜치           | `develop`으로 바꾼다. 새 프로젝트의 기본값은 `main`이다               | `develop`에 push해도 주소에 반영되지 않는다        |
| Routing Rules 모드 | **Regex**로 등록한다. Path pattern(`/api/:path*`)은 쓰지 않는다 | `:path*`가 글자 그대로 넘어가 모든 요청이 404가 된다   |
| Routing Rules 반영 | **Save** → **Test Rules**로 확인 → **Publish**          | Save만 하면 스테이징에 머물고 반영되지 않는다           |

잘못 Publish했으면 Routing Rules의 **History** 탭에서 이전 버전으로 되돌린다.
