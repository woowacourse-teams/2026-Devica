# Devica MVP — 유스케이스 및 화면 동작

> 팀 공통 개발 기준 문서. AI에게 작업을 시킬 때 이 파일을 컨텍스트로 함께 전달한다.
> 원본 유스케이스 명세의 요약본이며, 상세 흐름은 원본을 따른다.
> 색상·타이포·간격 등 디자인 토큰은 [디자인 시스템](design/디자인_시스템.md)을 따른다.
>
> **화면·흐름·용어는 이 문서가 기준이다.** [와이어프레임](wireframes)과 어긋나면 이 문서가 맞다.
> 와이어프레임은 특정 시점의 스냅샷이라 먼저 낡는다.

---

## 1. 시스템 한 줄 정의

사용자가 **제품 → 사용 목적 → 권장 사양(필요 시 조정)** 순으로 구매 조건을 확정하고,
그 조건에 맞는 전자제품 목록을 **검색 · 필터 · 정렬**해서 확인하는 서비스.

## 2. 액터

| 액터 | 설명 |
| --- | --- |
| 사용자 | 모든 유스케이스의 주 액터 |
| 제품 정보 제공 시스템 | 외부 시스템. UC-07(제품 검색)에서만 관여 |

## 3. 전체 흐름

```
[메인]
  └ UC-01 제품 선택
      └ UC-02 사용 목적 선택
          └ UC-03 권장 사양 확인
              ├─(조정함)→ UC-04 제품 사양 조정
              │              └ UC-05 선택 내용 확인 ⇄ UC-06 선택 내용 수정
              │                     └ UC-07 제품 검색
              └─(조정 안 함)────────────→ UC-07 제품 검색
                                              ├ UC-08 검색 조건 설정 (재검색)
                                              ├ UC-09 제품 정렬
                                              └ UC-11 제품 상세 조회

[가이드 탭] ─ UC-10 제품 가이드 조회 → (선택 시) 제품 검색 화면으로 이동
```

## 4. 온보딩 중 유지되는 상태

검색 요청 시점에 아래 값이 모두 확정되어 있어야 한다.

| 상태 | 생성 | 변경 | 비고 |
| --- | --- | --- | --- |
| 선택한 제품 | UC-01 | — | 이후 단계에서 변경 흐름 없음 |
| 사용 목적 | UC-02 | — | MVP는 백엔드 목적만 제공 |
| 권장 사양 | UC-03 | UC-04 | 제품 + 사용 목적으로 결정 |
| 최종 사양 | UC-04 | UC-06 | 조정 없으면 권장 사양 = 최종 사양 |
| 검색 조건 | UC-08 | UC-08 | 검색 결과 화면에서만 적용 |
| 정렬 기준 | UC-09 | UC-09 | 결과가 0건이면 미적용 |

### 4.1 최종 사양과 검색 조건의 관계 — 덮어쓰기

**최종 사양은 검색 조건의 초기값으로 들어간다.** 사용자가 UC-08에서 값을 바꾸면
그 값이 검색 조건이 되고, 최종 사양은 더 이상 검색에 관여하지 않는다.

```
최종 사양 RAM 32GB → 검색 조건 RAM 초기값 32GB
                   → 사용자가 16GB로 변경
                   → 검색은 16GB 기준으로 수행
```

두 값을 AND로 쌓지 않는다. 모순 조합이 생겨 결과가 항상 0건이 된다.

### 4.2 상태 저장 방식

| 대상 | 처리 |
| --- | --- |
| 검색 시점의 조건 | **미확정.** URL 쿼리 파라미터 권장 — 새로고침·공유·뒤로가기·GA 집계가 함께 해결된다 |
| UC-04 진행 중의 중간 답변 | **저장하지 않는다.** 새로고침하면 첫 질문부터 다시 시작한다 |

## 7. 공통 규칙

1. 온보딩 화면(UC-02, UC-04)은 **진행 상태를 표시**한다.
2. 사용자가 값을 바꾸지 않으면 **기존 값을 유지**한다. (UC-04 3a, UC-06 3a)
3. 조건에 맞는 제품이 0건이면 **검색 결과 없음 화면**을 표시한다. (UC-07 5a, UC-08 5a)
4. 외부 제품 정보 조회 실패 시 **오류 화면**을 표시한다. (UC-07 3a)
5. 사양 조정은 **선택지 기반**이다. 자유 입력이 아니다. (UC-04)
6. MVP 범위: 사용 목적은 **백엔드만** 제공한다. (UC-02)
7. **다음 단계로 넘어가는 버튼은 선택이 완료되기 전까지 비활성**이다.
8. **브라우저 뒤로가기는 이전 단계로 이동**한다. UC-04 첫 질문에서 뒤로 가면 UC-03으로 간다.
9. **UC-04는 화면 하나다.** 질문 수만큼 반복하며, 질문은 데이터 배열로 관리한다. 질문이 늘어도 화면을 추가하지 않는다.
10. UC-11에서 뒤로 가면 **검색 결과의 스크롤 위치를 복원**한다.
11. 외부 구매처 링크는 **새 탭**으로 연다.
12. **아직 지원하지 않는 항목은 `준비 중` 배지로 명시**한다. 회색 처리만으로는 왜 눌리지 않는지 알 수 없다. (UC-01의 기타 제품, UC-02의 미지원 목적, UC-10의 미작성 가이드)

## 8. 화면 상태

각 화면은 아래 상태를 정의한다. 해당 없으면 "없음"으로 표기한다.

### 8.1 로딩

**별도 라우트를 두지 않는다.** 화면 내부의 상태로 처리한다.
`/loading` 경로를 만들면 결과 화면에서 뒤로가기를 눌렀을 때 빠져나올 수 없다.

| 상황 | 표현 |
| --- | --- |
| 최초 검색 (UC-07) | 전체 화면. 인디케이터 + "조건에 맞는 제품을 찾고 있습니다" + 선택한 사양 요약 ([와이어프레임](wireframes/제품_검색_로딩.png)) |
| 재검색 (UC-08 · UC-09) | 목록 영역만 스켈레톤. 헤더·필터는 그대로 유지해 조작을 막지 않는다 |

**최소 표시 시간이 필요하다.** 제품이 20대 안팎이라 응답이 0.2초에 올 수 있고,
그러면 로딩이 깜빡여 화면이 번쩍이는 것처럼 보인다. 아래 중 하나를 택한다. (**미정**)

```
A. 로딩을 띄웠으면 최소 500ms는 유지한다.
B. 200ms 안에 응답이 오면 로딩을 아예 띄우지 않는다.
```

의도적인 지연 연출은 넣지 않는다.

### 8.2 결과 없음 (UC-07 5a, UC-08 5a)

| 요소 | 내용 |
| --- | --- |
| 메시지 | "조건에 맞는 제품이 없습니다" |
| 안내 | 현재 적용된 검색 조건을 함께 표시 |
| 대안 | `전체 제품 보기` — 조건 없는 목록으로 이동 |

사용자가 검색 조건을 직접 조작해 범위를 넓힌다.
자동 조건 완화는 MVP 범위에서 제외한다. GA로 발생 빈도를 측정하고 필요하면 도입한다.

### 8.3 오류 (UC-07 3a, UC-11 3a)

| 요소 | 내용 |
| --- | --- |
| 메시지 | "제품을 불러오지 못했습니다" |
| 행동 | 재시도 버튼 |

UC-11에서 존재하지 않는 제품 ID로 접근하면 "존재하지 않는 제품입니다"를 표시한다.

## 9. 사양 항목 규칙

사양 항목은 **PROCESSOR · MEMORY · STORAGE · OS** 네 개다.
UC-03 · UC-05 · UC-07 · UC-10 · UC-11에서 모두 같은 표기를 쓴다.

### OS와 PROCESSOR는 연동된다

두 값은 독립적이지 않다. 불가능한 조합을 만들 수 없어야 한다.

| OS | PROCESSOR 선택지 |
| --- | --- |
| Mac | Apple M 시리즈 |
| Windows | Intel · AMD 계열 |

**OS를 변경하면 PROCESSOR를 해당 OS의 권장값으로 자동 변경한다.**
사용자가 조합을 직접 맞추게 두면 결과 0건이 반복된다.

자동 변경 시 **안내를 표시한다.** 고른 값이 말없이 바뀌면 오작동으로 받아들인다.

> "운영체제에 맞춰 프로세서를 변경했습니다"

## 10. 용어 사전 (표기 고정)

| 용어 | 의미 | 혼용 금지 |
| --- | --- | --- |
| 제품 | 사용자가 추천받으려는 전자제품 종류 | 기기, 디바이스 |
| 사용 목적 | 제품을 쓰는 용도 (MVP: 백엔드) | 용도, 직군, 페르소나 |
| 권장 사양 | 제품 + 사용 목적으로 시스템이 제시하는 기본 사양 | 추천 사양, 기본값 |
| 최종 사양 | 조정 후 확정되어 검색에 쓰이는 사양 | 조정 사양, 확정 스펙 |
| 검색 조건 | 검색 결과 화면에서 추가로 거는 조건 | 필터, 사양 |
| 제품 검색 | 조건에 맞는 제품 목록 조회 | 제품 추천, 결과 조회 |

## 11. AI 활용 규칙

- 이 문서를 **컨텍스트로 먼저 제공**한 뒤 작업을 요청한다.
- 화면·API·도메인 명칭은 **10절 용어 사전을 그대로 사용**한다.
- 이 문서에 없는 기능·화면·필드는 **AI가 임의로 추가하지 않는다.** 필요하면 12절에 질문으로 남긴다.
- 작업 단위는 **유스케이스 ID 기준**으로 지시한다. (예: "UC-07 제품 검색의 3a 실패 처리 구현")

## 13. 검색 조건과 정렬 (UC-08 · UC-09 확정)

### 13.1 검색 조건 항목

와이어프레임([제품 검색 결과](wireframes/제품_검색_결과.png))대로 **네 개**를 둔다. 모두 정확히 일치가 아니라 범위 조건이다.

| 항목 | 의미 | 선택지 |
| --- | --- | --- |
| 가격 | 선택값 **이하** | 150만 · 200만 · 250만 · 300만 · 400만 · 500만원 |
| CPU | 선택한 OS의 해당 등급 **이상** | OS별 등급표(9절). `맥`·`윈도우`로 묶어 표시 |
| RAM | 선택값 **이상** | 목록에 있는 메모리 용량 |
| 저장장치 | 선택값 **이상** | 목록에 있는 저장 용량 |

**선택지는 현재 목록에 실제로 있는 값만 만든다.** 최저가가 209만원이면 `150만원 이하`·`200만원 이하`는 노출하지 않는다. CPU도 제품이 없는 등급은 바로 아래 등급과 결과가 같아 뺀다.

고를 값이 하나뿐인 항목은 **비활성으로 두고 `선택지 없음`이라고 적는다.** 흐리게만 두면 왜 못 고르는지 알 수 없다(7절 12번과 같은 이유).

### 13.2 정렬 기준

| 값 | 표시 | 규칙 |
| --- | --- | --- |
| `RECOMMENDED` | 추천순 | 권장 사양과 가까운 순 → 가격 낮은 순 |
| `PRICE_ASC` | 가격 낮은 순 | |
| `PRICE_DESC` | 가격 높은 순 | |

세 기준 모두 마지막 동점은 **제품 ID 오름차순**으로 가른다. 정렬을 바꿀 때 값이 같은 제품끼리 자리가 뒤바뀌면 목록이 흔들리는 것처럼 보인다.

**추천순은 권장 사양과의 거리를 잰다.** 세 축의 거리를 더하고, 작을수록 위로 올린다. 0이면 사양이 정확히 맞는 제품이다.

| 축 | 거리 | 예 (권장 `P_HS / 32GB / 512GB`) |
| --- | --- | --- |
| CPU | 등급표 인덱스 차이의 절댓값 | `HX` → 2 |
| RAM | `｜log2(제품 ÷ 권장)｜` | `64GB` → 1 |
| 저장장치 | `｜log2(제품 ÷ 권장)｜` | `2TB` → 2 |

용량은 배수로 오르므로 log2로 재야 "CPU 한 등급 차이 ≈ 용량 두 배"로 같은 눈금에 놓인다. 등급표 인덱스로 재면 `36GB`처럼 선택지에 없는 값에서 깨진다.

**모자란 쪽도 거리로 센다.** 부호를 남기면 사양 미달 제품의 거리가 음수가 되어 딱 맞는 제품보다 위로 올라간다. UC-07 매칭 결과에는 미달 제품이 없지만 전체 제품 목록에는 있다.

**제품은 자기 OS의 권장 사양과 견준다.** Mac과 Windows가 섞인 목록에서도 각자의 기준으로 잰다.

**정렬 대상에 CPU 성능 순은 없다.** Mac 3단계와 Windows 4단계는 체계가 달라 하나로 줄 세우면 "Windows H가 Mac PRO보다 위" 같은 근거 없는 서열이 생긴다. 추천순의 CPU 거리는 **같은 OS 안에서만** 재므로 이 문제가 없다.

### 13.2.1 추천순을 언제 쓸 수 있나

| 상황 | 추천순 | 기본 정렬 |
| --- | --- | --- |
| 최종 사양 확정 전 (UC-01 전에 헤더로 진입) | 노출하지 않음 | 가격 낮은 순 |
| 추천 목록 (UC-07) | 노출 | **추천순** |
| 전체 제품 목록 | 노출 | 가격 낮은 순 |

견줄 사양이 없으면 추천순이라는 개념 자체가 없으므로 선택지에서 내린다. 추천 목록은 권장 사양이 곧 목적이라 추천순으로 열고, 전체 제품 목록은 훑어보는 곳이라 가격순으로 연다.

### 13.3 4.1의 덮어쓰기 규칙을 대체한다

4.1은 최종 사양과 검색 조건을 AND로 쌓지 말라고 했다. 모순 조합으로 결과가 항상 0건이 되는 것을 막기 위해서였다.

**13.1의 "있는 값만 선택지로 만든다"가 그 사고를 원천적으로 없앤다.** 고를 수 있는 값은 모두 최소 1건을 보장하므로, 검색 조건은 최종 사양 매칭 결과 위에 AND로 얹는 단순한 구조로 둔다. 최종 사양을 덮어쓰지 않는다.

조건을 **여러 개 겹치면** 여전히 0건이 될 수 있다. 그때는 8.2대로 처리하되 대안은 `전체 제품 보기`가 아니라 **`검색 조건 지우기`**다. 조건 때문에 비었으니 조건을 지우는 것이 바로 맞는 행동이다. 조건 없이 0건이면(사양이 높은 경우) 기존대로 `전체 제품 보기`를 준다.

### 13.4 조작 기록

`SEARCH_CONDITION_CHANGED`와 `PRODUCT_SORT_CHANGED`를 **PostHog에만** 보낸다. `ExperimentEventName` enum에 없는 이름은 서버가 400으로 막기 때문이며, `QUESTION_SKIPPED`·`PRODUCT_DETAIL_VIEWED`와 같은 처리다. DB 집계가 필요해지면 그때 enum을 확장한다.
