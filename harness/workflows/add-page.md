# 화면 추가

시작 전에 [`harness/rules/스타일.md`](../rules/스타일.md)를 연다.

각 단계는 **확인 질문**이다. 규칙 자체는 [`AGENTS.md`](../../AGENTS.md)와 `rules/`에 있다.

## 디렉터리

```
src/main/java/com/wrb/devica/<도메인>/
    <도메인>Controller.java
    <도메인>Service.java
    <화면>Response.java          같은 패키지에 둔다. dto/ 를 만들지 않는다

src/main/resources/
  templates/
    pages/                       라우트 경로를 그대로 따른다
    fragments/                   라우트 없는 조각
  static/
    css/    tokens.css · base.css · components/ · pages/
    fonts/

src/test/java/com/wrb/devica/<도메인>/
    <도메인>ControllerTest.java
```

**없는 디렉터리는 그 단계에 도달했을 때 만든다.** 미리 만들지 않는다.

## 1. 스펙 태깅 게이트

**라우트와 응답 객체 구조를 여기서 확정한다.** 아래에 답하고 각 항목에 [HUMAN]/[AI]를 붙인다.
**[AI]가 하나라도 남으면 2단계로 넘어가지 않는다.**

- 이 화면은 `docs/MVP_유스케이스.md`의 어느 UC인가? 문서에 없으면 시작하지 않는다
- 라우트 경로의 근거는 무엇인가? **§6은 "제안"이라고 명시되어 있고 §12에 미확정으로 남아 있다.** 별도로 확정된 적이 없으면 [AI]다
- 화면에 표시할 필드 목록의 근거는 어디인가? (유스케이스 본문 / `docs/wireframes/`)
- 빈 상태를 정의했나? (§8.2)
- 에러 상태를 정의했나? (§8.3)
- 폼이 있다면 전송 방식과 **검증 실패 시 어디로 가는지**를 정했나?
- 공유 fragment를 쓴다면 **넘길 파라미터 구조**를 정했나?
- 이 화면에서 쓰는 용어가 §10 용어 사전과 일치하나?

## 2. 응답 객체

컨트롤러가 이 타입을 인자로 필요로 하므로 **먼저 만든다.**

- 이름이 `<화면>Response`인가? (`ProductListResponse`, `ProductDetailResponse`)
- 도메인 패키지에 바로 두었나? `dto/`를 만들지 않았나?
- `record`인가?
- **각 필드를 템플릿에서 가공해야 하나?** 그렇다면 필드가 잘못됐다. 포맷은 서비스에서 끝낸다 — `1290000L`이 아니라 `"1,290,000원"`이 담겨야 한다
- 엔티티 타입이 필드에 섞이지 않았나?
- 목록이라면 항목 타입을 중첩 `record`로 두었나?
- **그 항목 타입을 공유 fragment가 받나?** 그렇다면 중첩하지 말고 독립 파일로 뺀다. 다른 화면이 남의 응답 객체 내부를 참조하게 된다

## 3. 서비스 메서드

- 반환 타입이 2단계에서 만든 Response인가?
- **포맷팅·조건 분기·연관 데이터 조합이 이 메서드 안에서 끝났나?**
- 엔티티가 이 메서드 밖으로 나가지 않나?

## 4. 컨트롤러 메서드

- **서비스 호출 한 번 / Model 담기 / 뷰 이름 반환** — 이 셋 말고 다른 게 있나?
- 뷰 이름이 라우트 경로와 같은가? (`/onboarding/purpose` → `"pages/onboarding/purpose"`)
- Model에 담는 키 이름이 템플릿에서 쓰는 이름과 같은가?

## 5. 템플릿 파일 생성

- `templates/pages/` 아래 **라우트와 같은 경로**에 두었나?
- 공통 레이아웃 fragment를 쓰는가? 전체 HTML을 다시 쓰지 않았나?
- **값을 계산·가공하는 표현식이 있나?** 있으면 2단계로 돌아간다
- `th:each` / `th:if` 외의 로직이 있나?
- 1단계에서 정의한 **빈 상태·에러 상태 마크업**이 있나?

## 6. 정적 리소스 연결

- CSS를 `@{/css/...}`로 참조했나? 절대·상대 경로 문자열을 쓰지 않았나?
- 새로 쓴 색·간격·타이포가 **`tokens.css` 변수**인가? 값을 직접 쓰지 않았나?
- `components/`에 만든 파일이 **디자인 시스템 §컴포넌트에 이름이 있는 것**인가? 없으면 `pages/`다
- 인라인 `style` 속성이나 `<script>` 블록이 있나?
- 필요한 폰트 파일이 `static/fonts/`에 있나? **없으면 여기서 멈추고 요청한다. CDN을 쓰지 않는다**

## 7. 컨트롤러 테스트

**슬라이스 테스트만 쓴다.** 웹 계층만 띄우고 서비스는 가짜로 채운다. DB를 띄우지 않으므로
Docker 없이 돌고 1~2초에 끝난다.

- 뷰 이름을 검증했나?
- **Model에 담긴 타입이 Response인가?** (엔티티가 아닌가)
- 애노테이션 이름을 **공식 문서에서 확인했나?** Spring Boot 4 기준이다. 스타터가 세분화된 전례가 있으므로 검색 결과의 3.x 코드를 그대로 쓰지 않는다

E2E는 여기서 하지 않는다. 화면 단위가 아니라 **흐름 단위로 따로** 한다.
