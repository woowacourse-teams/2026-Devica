# 빌드·설정 규칙

**의존성·설정 파일 작업 전에 연다.**

각 설정이 왜 그렇게 되어 있는지는 [`docs/개발_환경_가이드.md`](../../docs/개발_환경_가이드.md) §4와 §6에 있다.
이 문서는 AI가 지켜야 할 것만 적는다.

## Gradle

- 항상 `./gradlew` (Windows는 `.\gradlew.bat`)를 쓴다. 로컬에 설치된 `gradle`을 쓰지 않는다 — Wrapper가 버전을 고정한다
- `gradle/wrapper/` 아래 파일을 수정하지 않는다
- PR 전 `./gradlew build`로 확인한다 (개발 환경 가이드 §5)

## 의존성

- **의존성 추가는 사람이 결정한다. AI는 `build.gradle`을 수정하지 않는다.** 필요하면 무엇을 왜 추가해야 하는지 제안하고 멈춘다
- **버전을 명시하지 않는다.** Spring Boot BOM이 검증된 조합을 관리한다. 임의로 적으면 호환성이 깨진다 (§4-2)
- 새 라이브러리로 해결하기 전에 **이미 들어와 있는 것으로 되는지 먼저 확인한다.** `build.gradle`을 열어본다
- Spring Boot 4에서 스타터가 세분화됐다. 검색 결과에 나오는 3.x 좌표(`spring-boot-starter-web`, `spring-boot-starter-test`)를 그대로 쓰지 않는다. 현재 좌표는 `build.gradle`을 보고 맞춘다
- 4.x 자료가 부족하다. **공식 문서를 1차 출처로 삼는다** (§6-1)

## 설정 파일

아래 파일은 **수정하지 않는다.** 값이 필요하면 제안하고 멈춘다.

- `src/main/resources/application.yml`
- `src/main/resources/application-local.yml`
- `src/test/resources/application.yml`
- `docker-compose.yml`

**특히 포트는 파일에서 고치지 않는다.** 환경변수 `DB_PORT` / `TEST_DB_PORT`를 쓴다.
설정 파일을 고치면 그 수정이 PR에 섞여 다른 팀원의 환경을 깨뜨린다 (§4-5, §9).

`src/main/resources/application.yml`은 **테스트에서 로드되지 않는다.** 이름이 같은
`src/test/resources/application.yml`이 대체한다. 테스트에 필요한 값은 그쪽에 따로 있다 (§4-6).

## 환경변수

- **`.env` 파일을 도입하지 않는다.** 클론 직후 바로 실행되는 상태를 유지하는 게 더 중요하다는 판단이 이미 있다 (§4-1)
- 새 환경변수가 필요하면 제안하고 멈춘다

## 커밋 금지

`.gitignore`에 있는 것에 더해:

- `CLAUDE.md`, `.claude/`, `.codex/` — 도구별 개인 설정이다. 저장소에는 `AGENTS.md`와 `harness/`만 커밋한다
- 운영 자격증명, `application-prod.yml`, `*.env`
- 포트를 바꾼 `docker-compose.yml` / `application-local.yml` — 각자 환경 문제라 공유 파일에 섞이면 안 된다
- 라이선스 파일 없는 폰트 파일
