# 스타일 규칙

**CSS·마크업 작업 전에 연다.**

값의 기준은 [`docs/design/디자인_시스템.md`](../../docs/design/디자인_시스템.md)의 **frontmatter**다.
이 문서는 그 값을 *어떻게 쓰는지*만 정한다. 값 자체를 여기 옮겨 적지 않는다.

## 파일 구성

```
src/main/resources/static/
  css/
    tokens.css      frontmatter → CSS 변수. 값을 적는 유일한 파일
    base.css        @font-face · 리셋 · 타이포 · 레이아웃 컨테이너
    components/     디자인 시스템에 이름이 있는 컴포넌트만
    pages/          화면 전용 스타일. templates/pages/ 와 같은 경로
  fonts/
```

`components/`와 `pages/`는 **미리 만들지 않는다.** 첫 파일이 생길 때 만든다.

## 값은 변수로만 참조한다

`tokens.css`의 변수 이름은 **frontmatter 키를 그대로** 쓴다. 문서와 CSS가 1:1이라
"이 값이 어디서 왔나"를 검색 한 번으로 확인할 수 있다.

`colors`와 `spacing`은 평면 구조라 키가 그대로 변수명이 된다.

```css
--surface-container-lowest: #ffffff;   /* colors.surface-container-lowest */
--gutter: 16px;                        /* spacing.gutter */
```

`typography`만 2단 중첩이라 **`--<스타일>-<속성>` 으로 평탄화**한다. 속성 이름은 케밥으로 바꾸되
글자를 바꾸지 않는다 (`fontSize` → `font-size`).

```css
--body-md-font-size: 14px;             /* typography.body-md.fontSize */
--body-md-line-height: 1.5;            /* typography.body-md.lineHeight */
--label-md-letter-spacing: 0.05em;     /* typography.label-md.letterSpacing */
```

**변수 이름을 frontmatter에서 되짚어갈 수 없으면 그 자체로 위반이다.** 이름을 줄이거나
(`--body-md-size`) 다른 말로 바꾸지(`--text-body`) 않는다.

- 색·간격·타이포 값을 CSS에 직접 쓰지 않는다. `#ffffff`가 아니라 `var(--surface-container-lowest)`, `16px`이 아니라 `var(--gutter)`
- **필요한 값이 frontmatter에 없으면 새 변수를 만들지 말고 멈추고 물어본다.** 토큰 추가는 디자인 결정이지 구현 판단이 아니다
- 간격은 4px 그리드를 벗어나지 않는다

## 폰트

폰트 파일은 `static/fonts/`에서만 참조한다. **외부 URL 금지, 예외 없음.**

- `@font-face`는 `base.css`에만 선언한다. 다른 파일에 중복 선언하지 않는다
- 필요한 파일: `PretendardVariable.woff2` (400·600·700을 한 파일이 덮는다), `Geist-Medium.woff2` (500), 각 OFL LICENSE
- **파일이 없으면 CSS를 쓰지 말고 추가를 요청한 뒤 멈춘다. CDN으로 대체하지 않는다**
- 새 폰트 추가는 의존성 추가와 같다. 제안만 하고 추가하지 않는다
- 레이블 내용이 한글이면 **크기·자간 토큰은 그대로 두고 `font-family`만 Pretendard로** 바꾼다 (디자인 시스템 §타이포그래피)

Inter는 호스팅하지 않는다. frontmatter의 `Pretendard, Inter`는 폴백 체인이고, 같은 문서에
"Pretendard는 Inter를 기반으로 만들어져 라틴 부분이 거의 그대로 맞아떨어진다"고 적혀 있다.
선언은 그대로 두되 파일은 Pretendard만 싣는다.

> **언제 이 규칙을 깨나** — 첫 로딩이 실제로 느리다고 느껴지면 그때 CDN 전환을 검토한다.
> 그 전에는 하지 않는다.

## 정적 리소스 경로

```html
<link rel="stylesheet" th:href="@{/css/base.css}">
<script th:src="@{/js/....js}"></script>
```

`@{...}`를 쓴다. 컨텍스트 경로가 붙어야 배포 환경에서 깨지지 않는다.
절대 경로 문자열(`/css/...`)이나 상대 경로(`../css/...`)를 직접 쓰지 않는다.

## 인라인 금지

- `style="..."` 속성 금지. 클래스로 뺀다
- 템플릿 안 `<script>` 블록 금지. 필요하면 `static/js/` 파일로 만들고 `@{...}`로 참조한다

## 컴포넌트 CSS 생성 기준

`css/components/`에 파일을 만들 수 있는 것은 **디자인 시스템 §컴포넌트에 이름이 있는 것만**이다.
이름이 없으면 만들지 않는다.

한 화면에서만 쓰는 스타일은 `css/pages/`에 둔다. 두 번째 화면에서 같은 게 필요해지면,
그때 디자인 시스템에 이름이 있는지 확인하고 있으면 `components/`로 옮긴다. 없으면 옮기지 말고
**이름을 붙일지 물어본다.**

> 디자인 시스템 §Spec Row는 "동일한 spec row가 추천·확인·목록·가이드·상세 화면에 등장한다.
> 모든 화면에서 똑같이 보여야 한다"고 명시한다. 이런 건 처음부터 `components/`다.

## 마크업

- 공통 레이아웃은 fragment로 만든다. 전체 HTML 중복 작성 금지
- **fragment는 파라미터로 받은 것만 출력한다.** fragment 안에서 계산하거나 조합하지 않는다
- 반복(`th:each`)과 표시/미표시 분기(`th:if`)까지만 허용한다. 그 외 표현식은 응답 객체가 잘못됐다는 신호다

## 반응형

- 브레이크포인트는 **768px 하나뿐**이다 (디자인 시스템 §레이아웃). 다른 값을 추가하지 않는다
- 고정 px 너비를 피하고 `max-width`와 `%`/`fr`을 쓴다
- 모바일 우선, 단일 컬럼. 사이드바는 이 제품에 없다
