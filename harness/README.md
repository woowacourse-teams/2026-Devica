# harness

AI 에이전트가 이 저장소에서 작업할 때 읽는 규칙 모음이다.

## 도구 중립

팀에서 Claude Code와 Codex를 함께 쓴다. **규칙은 두 도구에 동일하게 적용하되, 어떤 에이전트를
어떻게 쓸지는 각자 선택한다.** 그래서 저장소에는 도구 중립 파일만 커밋한다.

| | 커밋한다 | 커밋하지 않는다 |
|---|---|---|
| 규칙 | `AGENTS.md`, `harness/` | — |
| 도구 설정 | — | `CLAUDE.md`, `.claude/`, `.codex/` |

Codex는 `AGENTS.md`를 그대로 읽는다. Claude Code는 읽지 않으므로 각자 로컬에 한 줄짜리
`CLAUDE.md`를 만든다. 절차는 [`docs/개발_환경_가이드.md`](../docs/개발_환경_가이드.md) §3 Step 7에 있다.

## 구성

| 위치 | 성격 |
|---|---|
| [`../AGENTS.md`](../AGENTS.md) | **매 요청마다 주입된다.** 작업 종류와 무관하게 걸리는 규칙 |
| `rules/` | 특정 영역을 건드릴 때만 걸리는 제약. **순서가 없다** |
| `workflows/` | **순서가 있는** 절차 |

`AGENTS.md`에는 rules 문서를 **언제 여는지만** 남기고 내용은 옮기지 않는다.

## 새 규칙을 어디에 둘까

위에서부터 답한다.

1. **작업 종류와 무관하게 항상 걸리나?** → `AGENTS.md`
   계층 경계, 전역 금지, 스펙 태깅 게이트가 여기 해당한다.
2. **특정 영역을 건드릴 때만 걸리나?** → `rules/`
3. **순서가 있나?** → `workflows/`

### AGENTS.md에 넣지 않는 것

매 요청마다 주입되므로 **길이가 곧 비용이다.** 아래는 넣지 않는다.

- **LLM이 이미 아는 내용** — Thymeleaf 문법, Spring MVC 사용법, HTTP·JPA 기초
- **코드나 설정 파일을 열면 확인되는 사실** — 버전 번호, 디렉터리 목록, 의존성 좌표
- **`docs/` 문서에 이미 있는 내용** — 복사하지 말고 링크한다. 복사하면 원본이 바뀔 때 둘이 어긋나고, 어느 쪽이 맞는지 아무도 모르게 된다

## 워크플로는 언제 추가하나

**같은 절차를 실제로 반복한 뒤에만 추가한다.** 반복이 확인되지 않은 절차를 미리 만들면,
쓰이지도 않는 문서가 규칙인 척 남는다.

지금 `workflows/`에 `add-page.md` 하나뿐인 이유가 이것이다. 화면 추가는 MVP 화면 수만큼
확실히 반복된다. 나머지는 아직 한 번도 해보지 않았다.

## 규칙이 안 지켜지면

규칙을 늘리기 전에 **그 규칙이 필요한지 다시 본다.** 아무도 지키지 않는 규칙이 문서에 남아
있는 상태가 가장 나쁘다. 이건 [`docs/팀_컨벤션.md`](../docs/팀_컨벤션.md) 부록과 같은 원칙이다.

규칙을 바꾸면 **같은 PR에서 이 문서들을 고친다.**
